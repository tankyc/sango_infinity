## 三、本轮新增（阶段一）

### 3.1 `PersonAddAttribute` —— 人物常驻五维

```
{ "class": "PersonAddAttribute", "stat": 3, "value": 5 }        // 政治 +5
{ "class": "PersonAddAttribute", "stat": 4, "value": -10 }      // 魅力 -10
{ "class": "PersonAddAttribute", "stat": 0, "mode": 1, "value": 10 }  // 统率 +10%（按裸值）
```

- `stat`：0 统率 / 1 武力 / 2 智力 / 3 政治 / 4 魅力
- `mode`：0 加算（默认）/ 1 按"裸值"百分比
- 与 `TroopAddPersonAttribute` 的分工：本类**不出征也生效**（内政 / 登用 / 搜索 / 单挑都读 `Person.Politics` 等）；
  后者只在 `Troop.CalculateAttribute` 内按条件叠加。
- 实现：`PersonPassiveRule.Rebuild` 在 `Person.InitPersonActions` 里按当前特技集合重算，先清零再累加 → 天然可逆。
- 覆盖条目：佐治、识兵、治阵、尚勇、智佐、仪望、奋威、骁锐、佐幕、秉政、英仪、励治、昏庸、逸志、独断、畏阵、败节、江雄、恶来、死烈、武圣、陷营（部分）、威震（部分）等 14 条纯五维条目。

### 3.2 `PersonAddExpFactor` —— 经验倍率

```
{ "class": "PersonAddExpFactor", "type": 1, "value": 200 }   // 能力经验翻倍
```

- `type`：0 武将等级经验 / 1 能力经验 / 2 兵种适性经验
- `mode`：0 乘算叠加 / 1 直接设值
- 落点：`Person.GainExp` / `GainStatExp` / `GainJobAttributeExp` / `GainAbilityExp`，与剧本参数倍率**相乘**。
- 覆盖条目：苦学、幼麟、传道、授业、辨经（本人部分）。

### 3.3 `PersonMonthlyEffect` + `FeatureMonthlyEffectSystem` —— 月初结算

单条 Action 承载 11 种效果，由月度系统统一遍历在册武将（人在野外 / 未编队也生效）：

| type | 含义 | 对应条目 |
|---|---|---|
| 0 | 忠诚设值 | 守节（月初忠诚 = 150） |
| 1 | 忠诚加减（本人） | — |
| 2 | 功绩加减 | 清节、荫泽（反向） |
| 3 | 同城武将忠诚加减（scope 0/1/2） | 谏议、蠹政、行间 |
| 4 | 吸取同城武将功绩 | 荫泽 |
| 5 | 恢复伤病（scope 0 本人 / 其他 同城） | 疗疾、济世 |
| 6 | 向同城空闲武将传授能力经验（stat / value / threshold） | 传道、授业、辨经 |
| 7 | 消耗功绩换五维（stat = -1 取最低项） | 攘功 |
| 8 | 势力技巧点（securityDiv 按城治安折算，oncePerForce 去重） | 达识、鸿儒、崇文、穷经、肃纪 |
| 9 | 所在城治安加减 | 横征 |
| 10 | 所在城兵力增加 魅力 × value | 冠冕 |

### 3.4 `CityProductGainMonthly` —— 据点每月兵装产出

```
{ "class": "CityProductGainMonthly", "storeKind": 5, "mode": 1, "value": 5 }
```

- `storeKind`：1 剑 / 2 枪 / 3 戟 / 4 弩 / 5 马（= `ItemStoreKindType`，同时是兵装 `ItemType` 的 Id）
- `mode`：0 固定 / 1 政治 × value / 2 现有库存 × (value-100)%
- `oncePerCity`：同城同特技每月只结算一次（默认 false = 每个持有者各产一份）
- 覆盖：良工（枪/戟/弩）、马政、亲羌、绥乌、亲夷、绥蛮、王佐（产量部分）。
- 上限口径与生产/运输完全一致：`ItemType.TransformLimit(StoreLimit)`（见 `CityAI.cs:3676-3691`）。
  兵装四类在 `ItemTypes.json` 里没有 `p1`（= 0），`TransformLimit` 直接返回 `StoreLimit`，
  即"每类各能存到整个仓库上限"；船/攻城器械 `p1 = 10` 时才按 1% 折算。

### 3.5 `CitySearchingExtraEffect` —— 搜索额外奖励

```
{ "class": "CitySearchingExtraEffect", "probability": 5000, "gold": 50 }
```

- 参数：`probability`（万分比）、`gold`、`food`、`security`、`troops`、`troopsByGlamour`、`loyalty`、`actionPoint`、`techniquePoint`
- 时机：`OnCityJobSearchingSettled`（搜索演出结束后），只对"装配自己的那个武将"生效。
- 覆盖：得财、察弊、横暴、苛敛、抚众、营私、简政、煽乱、清议（技巧点部分）。

### 3.6 战斗类扩展

| 类 | 新增参数 | 对应条目 |
|---|---|---|
| `TroopDefeatEnemyEffect` | `rangeFromDestroyed`（范围圆心取败军位置） | 崩营、威震、隙击、荡营、摧阵、抚民、江虎、恶来 |
| `TroopDefeatEnemyEffect` | `injureEnemyLeader` / `injuryLevel`（击破致敌主将负伤） | 锦骑、死烈 |
| `FeatureCombatDuelEffect` | `injure` / `injuryLevel`（单挑后使目标主将负伤） | 搦战、虎啸、喝阵的延伸 |

顺带修掉一个链路缺陷：`TroopDefeatEnemyEffect` 原来在 `bound <= 0` 时整条 `return`，
导致"学敌将特技""使敌将负伤"这类**无半径**条目即使配了也永不触发。现已拆成
`ApplyRangeEffects` 单独受 `bound` 控制。

## 七、数据结构改造：特技表 `SangoObjectSet` → `SangoObjectMap`

### 7.1 改了什么

`ScenarioCommonData.Features` 的容器由 `SangoObjectSet<Feature>`（按 Id 直接下标的稀疏数组）
改为 `SangoObjectMap<Feature>`（`Dictionary<int, Feature>`），转换器同步换成
`SangoObjectMapConverter<Feature>`。

### 7.2 为什么改

| 维度 | 改造前（Set） | 改造后（Map） |
|---|---|---|
| 底层 | `Feature[32768]`（因为最大 Id = 32028） | `Dictionary<int, Feature>`，1496 条 |
| 引用数组内存 | 32768 × 8 B ≈ **256 KB**（其中 31272 个空槽） | 1496 × 约 40 B ≈ **60 KB** |
| `ForEach` 成本 | 每次扫满 32768 槽做 null 判断 | 只遍历真实条目 1496 次（**-95%**） |
| `Count` 语义 | 最大 Id + 1（32768），易被误用成循环上界 | 实际条数（1496） |
| `Get(id)` | 数组下标（含边界判断） | 字典查找，O(1) 同数量级 |
| 新增高 Id 特技 | 数组继续翻倍扩容 | 无额外成本 |

特技 Id 天然稀疏（1~100 原版 / 101~217 模组 / 30101~30162 本命 / 32000~32028 宝物），
属于"按 Id 查询、不按序号遍历"的数据，Map 是正确容器。

### 7.3 兼容性处理（改 Map 必须一起补的 5 处）

1. **`SangoObjectMap.ToArray()` / `ToString()` 重写** —— 基类实现是
   `for (i = 0; i < Count; i++) this[i]`；对 Map 而言 `this[i]` 是"按 Id 取"，
   Id 稀疏时**只会取到 Id < Count 的那几条，其余静默丢失**。已改为遍历字典。
2. **`SangoObjectMap.RandomGet()` 重写** —— 基类返回 null，依赖它的逻辑换容器后会静默失效。
3. **`SangoObjectMap.Sort(...)` 不再抛 `NotImplementedException`** —— 改为无操作并注明
   "Dictionary 不保证枚举顺序"，需要有序展示的调用方自行 `FindAll + List.Sort`。
   （仓库内现有 `Sort` 调用都作用于 List/Array，没有对 Database 调用的点）
4. **`SangoObjectMap.Remove(int id)`** —— 与 `SangoObjectSet.Remove(int)` 对齐，避免未来调用点编译失败。
5. **调用点改成基类/容器接口**：
   - `Scenario.Array2ObjectList` / `Id2Object` / `Id2Object0` 的参数 `SangoObjectSet<T>` → `Database<T>`；
   - `AbilityStudySystem.EnsureSkillAbilities` 里 `features.objects`（Set 专有数组）→ `features.ForEach(...)`。

### 7.4 不受影响的部分

- **JSON 结构不变**：两种转换器读的都是 `{ "Id": { ... } }`，`Features.json` /
  `Frontier*.json` 一行都不用改。
- **存档不变**：存档里记的是 `FeatureListId` / `features_list` 这类 `int[]`，
  读档时按 Id 查表，与容器实现无关。
- **UI 选择器不变**：`UIDataEdit` 的 `AddSetOptions / FindInSet / CollectCandidates`
  已经是 `Database<T>` 参数 + `ForEach`，换容器后反而少了 32768 次空扫。

| `TroopDefeatEnemyEffect` 范围圆心 | — | 只多读一次 `destroyed.cell` 引用，无分配 |
| `FeatureCombatDuelEffect` 负伤 | — | 仅命中时调用 `PersonInjury.Injure`，无分配 |

### 8.2 复杂度

| 场景 | 频次 | 改造后成本 |
|---|---|---|
| 剧本加载 | 1 次 | 特技表 1496 条 × 平均 1.2 个条目做一次 bool 标记（一次性）；`RebuildPersonPassive` = 人数 × 生效特技数（≤ 3~5），每人数次属性加减 |
| 月结 | 每年 12 次 | 人数 × 生效特技数的 flag 判断；只有配了月度效果的特技才解析 JSON（预计 < 30 条） |
| 换装 / 学特技 | 偶发 | 同"剧本加载"的单人部分，微秒级 |
| 战斗击破 | 每次击破 | 无新增循环；`rangeFromDestroyed` 只是换了 `Spiral` 的圆心 |

**结论：本批改动没有引入"每帧 / 每回合 × 全量对象"级别的开销**，
月结与读档的分配均已消除，主要成本从"扫 JSON"降为"读 bool"。
