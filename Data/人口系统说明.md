# 人口系统说明（HantuPopulation）

> 适用范围：`Project/Assets/Sango/Scripts/Game/System/Governance/HantuPopulation*.cs`
> 文档依据：按当前代码实现整理，公式与常量均可在源码对应行核对。

---

## 1. 概述

人口系统把「据点人口」拆成**城市人口（urban）**与**农村人口（rural）**两项资源，并为它们挂上
增长、城乡转化、迁徙、税收、征兵、灾害、劫掠、历史记录七条链路。

它是一套**可选规则**，与旧的单一人数模型并存：

| 模式 | 条件 | 行为 |
|---|---|---|
| 新人口（本系统） | `Variables.hantuPopulationEnabled == true` | 城乡双人口、季度结算、税收/征兵/治安/灾害全部走本系统 |
| 旧人口 | `Variables.populationEnable == true && !hantuPopulationEnabled` | `City.population` 单值 + 征兵直接扣人口 |
| 关闭 | 两者皆 false | 人口不参与任何结算 |

判定入口：

```csharp
// HantuPopulation.cs:8
public static bool Enabled => Scenario.Cur?.Variables?.hantuPopulationEnabled == true;
// ScenarioVariables.cs:552
public bool UseLegacyPopulation => populationEnable && !hantuPopulationEnabled;
```

**所有对外入口都自带 `Enabled` 短路**，关闭时不会改动任何数据，也不会产生日志与性能开销。

## 2. 数据模型

### 2.1 城市侧字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `City.population` | `int`（内部 `int?`） | 城市人口；未记录时读作 0，写一次即"已记录" |
| `City.ruralPopulation` | `int?` | 农村人口；`null` 表示未记录（区别于"显式 0"） |
| `City.HasRecordedPopulation` | `bool` | 是否有过显式记录 |
| `City.HasRecordedCommerce` / `HasRecordedAgriculture` | `internal bool` | 底表导入时的"是否已被覆盖"判据 |

> **重要**：`population` 的 setter **不做 clamp、不派发事件、不触发收获重算**。
> 任何"改完人口要立刻反映到收入"的地方，都必须自己调 `City.CalculateHarvest()`。

`ruralPopulation` 是可空的：`city.ruralPopulation.GetValueOrDefault()` 是读取的固定写法。

### 2.2 剧本侧字段

| 字段 | 说明 |
|---|---|
| `Variables.hantuPopulationEnabled` | 总开关 |
| `Variables.hantuPopulationGrowthPreset` | 增长预设，仅接受 3/4/5（其他值落回 4） |
| `Scenario.hantuPopulationSeason` | 季度幂等锁（`SeasonStamp`） |
| `Scenario.hantuPopulationHistory` | 历史快照与变动明细，惰性创建 |
| `Troop.hantuPopulationRaidTurn` | 上次劫掠回合，防同回合重复结算 |

## 4. 季度结算主流程

入口 `Scenario.OnSeasonStart` → `HantuPopulation.SettleSeason`，用 `SeasonStamp` 做幂等锁。

```
Prepare（补齐未初始化据点）
  ↓
按 Id 排序取全部存活据点（保证结算顺序稳定）
  ↓
① GrowAndConvert     自然增长 + 城乡转化
② MigrateToParent    关卡向所属城市迁徙
③ SettleRefugees     流民 / 异族归附
  ↓
写 hantuPopulationSeason
  ↓
CaptureQuarter       记录季度快照
  ↓
对每个有军团的据点 CalculateHarvest（让新人口立刻反映到下季收入）
```

一年 4 季、36 回合，即**每 9 回合结算一次人口**。

## 5. 自然增长

### 5.1 调用参数

| 项 | 城市人口 | 农村人口 |
|---|---|---|
| 容量 `capacity` | `UrbanCapacity` | `RuralCapacity` |
| 增长曲线容量 `growthCapacity` | 同 `capacity` | 港口 / 关卡 / 小城用 `RuralCapacity`，其余 **7,500,000** |
| 治安门限 `threshold` | **80** | **60** |
| `development` | `commerce%`（港口按 20%，关卡 0%，其余 100%） | `agriculture%`（同上） |
| `harvestBonus` | 丰收 +5% | 丰收 +25% |
| 政治 | 太守政治（0~100 截断） | 同 |

`bigCity` = 都市且 `specialty == 6`，增长结果额外 ×120%。

### 5.2 公式

```csharp
// HantuPopulationRules.cs:44-59
if (population <= 0 || population >= capacity || security <= threshold) return 0;

safety   = min(100, security) - threshold;
increase = sqrt(population)
         * (growthRate / 10000f)
         * CapacityModifier(population, growthCapacity)
         * (politics / 2 + development)
         * safety;

base = round(increase)                    // 银行家舍入 ToEven
if (bigCity) base = base * 120 / 100;
return min(capacity - population, base * (100 + harvestBonus) / 100);
```

增长预设 → `growthRate`：

| 预设值 | 名称（开局页） | growthRate |
|---|---|---|
| 3 | 初新 | 60 |
| 4 | 常规 | 50 |
| 5 | 挑战 | 40 |

### 5.3 容量修正曲线

```csharp
// HantuPopulationRules.cs:22-32
lower = growthCapacity * 2 / 100
upper = growthCapacity * 12 / 100
population < lower  →  lower / (population + ((lower - population) >> 4))   // >1，起步加速
population > upper  →  upper / (2 * population)                            // <0.5，后期减速
其余                →  1
```

以普通城市（growthCapacity = 150 万）为例：**3 万以下加速，18 万以上递减**；
农村（growthCapacity = 750 万）：**15 万以下加速，90 万以上递减**。

## 6. 城乡转化

只在**同一季度、同一次增长结算**里做一次，门限固定 90 治安。

```csharp
// HantuPopulationRules.cs:61-72
rollCount = 1 + (min(20, |security - 90|) >> 2);   // 1 ~ 6
CanConvertUrban(security) = security <= 90;         // 城市 → 农村
CanConvertRural(security) = security >= 90;         // 农村 → 城市
```

- **城市→农村**：`roll` 取 `1..rollCount`，迁移量 = `urban * roll%`，受农村容量限制。
- **农村→城市**：`requested = rural * roll% * 5 / max(1, rate)`，受城市容量限制。
  `rate` 是据点**粮价参数**（越大粮越便宜，见 `City.rate` 默认 50），粮价越高，进城越慢。
- 治安恰好 90 时两条分支都成立，按**先出城、再入城**的顺序执行。

抽样使用 `QuarterRoll(season, cityId, channel, count)`：

```csharp
// HantuPopulationRules.cs:87-96
seed = season * 0x9e3779b9 ^ site * 0x85ebca6b ^ channel * 0xc2b2ae35
     → 两次 xorshift 混合 → 1 + seed % choices
```

**确定性抽样**：同季度、同据点、同通道必得同一个数，**读档不重抽**，也不占用战斗随机序列。
通道分配：1 = 城市→农村，2 = 农村→城市，3/4 = 关卡迁徙（城市/农村），5 = 设施被毁，6 = 流民归附。

## 7. 关卡迁徙

只有**关卡**向所属城市迁移，且要求：

- 所属城市存在、存活、不是关卡
- 关卡与所属城市**同势力**

```csharp
// HantuPopulationRules.cs:74-78
Migration(source, destination, capacity, roll):
    if (source < destination * 50 / 100) return 0;      // 小户口不往大城搬
    return Transfer(source, destination, capacity, source * roll%);
```

城市人口、农村人口各掷一次（通道 3 / 4，`roll ∈ 1..5`），双向都记 `GateMigration`。

## 8. 经济影响

### 8.1 人口税（在总收获最后一步叠加）

```csharp
// HantuPopulation.cs:226-234
GoldTax = (int)(2.5 * sqrt(城市人口))
FoodTax = (int)(12  * sqrt(农村人口))
```

叠加位置：`ClassicsCityWorking.OnCityCalculateHarvest` 的最终结果之后——
即**不乘**治安/民心影响系数（`leftInfluence`），也**不乘**势力产出系数（`foodFactor` / `goldFactor`）。
人口税是独立加项。

### 8.2 建筑产出系数

```csharp
// HantuPopulationRules.cs:12-15
FacilityPercent(population, peoplePerPercent)
    = clamp(population / peoplePerPercent, 50, 150)   // 百分比，50% ~ 150%

MarketGold = 市场类建筑原值 × FacilityPercent(城市人口, 1000) / 100
FarmFood   = 农场类建筑原值 × FacilityPercent(农村人口, 4000) / 100
```

即：**每 1000 城市人口 +1% 市场金收入**，**每 4000 农村人口 +1% 农场粮收入**，
上下限 ±50%。非对应建筑原样返回，不受影响。

## 9. 征兵

### 9.1 可征上限

```csharp
// HantuPopulationRules.cs:110-115
RecruitLimit = 玩家：城市人口 + 农村人口
                AI  ：(城市人口 + 农村人口) * 2 + 1
```

它同时是**单次可征兵力上限**：`City.JobRecruitTroop` 里
`totalValue = min(totalValue, RecruitLimit(this))`，`BuildingWorking` 自动招募同样取 min。

为 0 时：`CityRecruitTroops.IsValid` 直接判定不可用，提示「可征人口不足」；AI 也会跳过征兵。

### 9.2 扣除量

```csharp
// HantuPopulationRules.cs:98-108
RecruitCost(troops, player) = troops * (player ? 100% : 50%)

RuralRecruitCost(total, grainRate) = total * (100 * grainRate) / (grainRate + 10) / 100
```

实际扣法（`GetRecruitmentCost`）：

1. 先扣农村，最多扣 `RuralRecruitCost`；
2. 差额由城市人口补；
3. 城市仍不足时再回补农村，保证"成功征到的兵一定足额扣人口"。

### 9.3 触发点

| 路径 | 位置 |
|---|---|
| 玩家/内政征兵 | `City.JobRecruitTroop` → `ChargeRecruitment` |
| 建筑/工作流自动招募 | `BuildingWorking`：按前后兵力差 `recruits` 扣人口 |
| UI 预览 | `UICityRecruitTroops`：显示「预扣人口 城市 X 农村 Y」 |

> AI 招募只扣**半价**人口，是刻意设计的难度补偿，不是 bug。

## 10. 治安

### 10.1 巡逻花费

```csharp
// HantuPopulationEconomy.cs:7-12
PatrolFee = (总人口 / 100000 + 1) * 50        // 每 10 万人一档，每档 50 金
```

替换的是 `CityJobType.Inspection` 的固定花费（`City.GetJobCost`）。
`OnCityCheckJobCost` 仍可在其后再改一次。

### 10.2 治安上限

```csharp
// HantuPopulationEconomy.cs:14-19
SecurityBaseline = min(100, 75 + 太守政治/10 + 最高政治/10 + (威压 ? 10 : 0))
```

- 太守不在城则按 0 政治计
- 威压特技 Id = **96**
- 该上限只约束**巡逻收益**，不约束其他治安来源

```csharp
// HantuPopulationEconomy.cs:21-24
LimitPatrolGain = max(0, min(gain, baseline - security))
```

已达上限时巡逻收益为 0 且**不消耗武将特性**（`City.cs` 里提前 return）。

## 11. 人口损失

| 来源（枚举） | 触发 | 损失 |
|---|---|---|
| `Disaster` | 蝗灾 | 城市 0~2%，农村 0~4% |
| `Disaster` | 疫病 | 城市 2~4%，农村 4~8% |
| `Siege` | 断粮且城边有敌军（`CostFood`） | 城市 5% |
| `CityCaptured` | 城破易主 | 城市 `50 - 魅力×0.3` %，农村 0 |
| `FacilityDestroyed` | 内政设施被敌军摧毁 | 农村 1~2% |
| `Raid` | 敌军劫掠 | 农村被迁走（见 §12） |

灾害损失的随机数**不消耗 GameRandom**，由 `cityId / SeasonStamp / month` 派生：

```csharp
// HantuPopulation.cs:265
seed = cityId*73856093 ^ SeasonStamp*19349663 ^ month*83492791
```

因此同回合同城反复触发灾害，掉的人口是同一个数。

## 12. 劫掠（Raid）

入口 `HantuPopulationIncidents.OnTroopTurnStart`，在**部队回合开始**时结算，每支部队每回合最多一次。

前置：

1. 人口开启，部队存活、兵力 > 0，且不是本回合已劫掠过的部队
2. `LandTroopType.isFight == true`（战斗陆军）
3. 所在格地形为 **草地(1) / 土(2) / 主径(11)**，且**格上无建筑**
4. 目标格属于敌方据点，己方有存活据点且同势力
5. 目标据点**没有**带 `hantuPopulationProtection` 的武将在职
6. 势力拥有劫掠资格（二选一）：
   - 科技 `hantuPopulationRaid == true`
   - 汉土地图（`mapType == "san11frontier"`）且拥有科技 **52163**（汉土「野外突击」）且是**骑兵**

迁移量：

```csharp
requested = min(敌方农村 * 2%, 部队兵力 / 5)
moved     = Transfer(敌方农村, 己方农村, 己方农村容量, requested)
```

劫掠量**转入主将所属据点**，双方各记一条 `Raid` 变化。

## 13. 流民归附

每季对所有**都市**（非关港）结算一次，要求在职武将持有对应特技：

| 类型 | 特技 | 增加量 |
|---|---|---|
| 流民归附 | 威压（96） | `(5 + 0~20) × 100`，即 500 ~ 2,500 |
| 异族内附 | 异族守备特技（按 `barbarianTribe` 查表） | `(10 + 0~40) × 100`，即 1,000 ~ 5,000 |

- 浮动值由 `QuarterRoll(SeasonStamp, cityId, 6, ...)` 决定，读档不重抽。
- 受农村容量约束，容量满则不加。
- 汉土地图兼容：`47000 + featureId`、威压额外兼容宝物版 **32025**。

## 14. 历史与总览

### 14.1 历史结构

```csharp
HantuPopulationHistory
  quarters : List<HantuPopulationQuarter>   // 季度快照，保留最近 24 季
  cities   : List<HantuPopulationCityChanges> // 每城变更明细，每城保留最近 24 条
```

- **同回合、同来源自动合并**：连续征兵 / 多次劫掠不会按调用次数撑大存档。
- 只记录**实际发生的变化**，不回推旧档、不补造历史。
- `Revision` 自增，供 UI 判断缓存是否失效。

### 14.2 变化来源（中文名见 `SourceName`）

自然增长、城乡转化、港关迁徙、征兵、灾害、围城损失、据点陷落、设施被毁、流民归附、
人口调整、初始人口、人口劫掠。

### 14.3 人口总览界面

入口：**右键菜单 / 情报菜单 →「人口总览」**（仅人口开启时出现）。
结构：

- 左：据点列表（按 `全图 / 城池 / 关隘 / 港口` 筛选，可按总人口/城市/农村排序）
- 右上：汇总卡片（人口合计、城市人口、农村人口、开发度）+ 汇总行（总人口、日期、最近季度净变）
- 右下：趋势折线图 + 人口变动记录（按来源分组，末尾提示保留上限）

## 15. 配置与数据

### 15.1 开局参数页

`UIScenarioVariables` 提供：

- **剧本人口开关**：`hantuPopulationEnabled`
- **人口增长预设**：初新 / 常规 / 挑战（映射 3 / 4 / 5）

### 15.2 剧本参数预设

`ScenarioVariablesPresetManager` 整体替换 `ScenarioVariables` 后，会补调
`Scenario.OnHantuPopulationModeChanged(wasEnabled)`，以便开关翻转时触发 `HantuPopulation.Refresh`。

### 15.3 人口底表

`Build/Content/Data/HantuPopulationProfiles.json`

```json
{
  "mapType": "san11frontier",
  "scenarioIds": [ 1001, 1002, "..." ],
  "source": "数据来源说明",
  "cities": {
    "3":  {"name":"广阳","x":356,"y":92,"buildingType":1,"urban":180000,"rural":760000,"commerce":88,"agriculture":64},
    "233":{"name":"虎牢關","x":331,"y":144,"buildingType":2,"urban":10000,"rural":50000}
  }
}
```

**六重校验**（任一不符就整份底表弃用，退回剧本自带数据/代码默认值）：

1. `mapType` 与剧本一致
2. 剧本 Id 在 `scenarioIds` 里
3. 据点 Id 在 `cities` 里
4. 名称一致
5. 坐标 `x/y` 与建筑类型 `buildingType` 一致
6. `urban / rural` 均存在且 ≥ 0

设计目的：防止地图改版后编号复用，把别处的人口错误导入本据点。

`commerce / agriculture` 为可选项，只在据点**没有**显式记录时才覆盖。

## 16. 扩展点

### 16.1 科技旗标 `Technique.hantuPopulationRaid`

在 `Techniques.json` 里给某条科技加 `"hantuPopulationRaid": true`，

## 17. 已知边界与注意事项

1. **改动人口不会自动重算收入**。写 `city.population` 后若要立刻生效，必须自己调 `CalculateHarvest()`；
   季度结算末尾已经替所有有军团的据点调过一次。
2. **`population` 无 clamp**。直接赋负值会污染后续所有 `sqrt` 与百分比计算，写入方需自行 `Math.Max(0, ...)`。
   系统内部所有扣减均已夹 0。
3. **治安 90 是唯一转化门限**，且转化方向随治安两侧自动切换，不存在"双向同时对冲"。
4. **围城损失在 `CostFood` 里两处判**（"缺粮但有存粮"、"完全断粮"），
   但一次结算只会命中其中一个分支，即**每回合最多扣一次 5%**。
5. **劫掠判定在部队回合开始**，与 `GameEvent.OnTroopTurnStart` 的派发顺序是"先劫掠、后广播",
   依赖 `OnTroopTurnStart` 的特技读到的是劫掠之后的人口。
6. **历史只增不减**：`quarters` 与每城 `changes` 都有硬上限（24），超出从最旧开始丢。
7. **底表只对新局生效**（`info.isSave == true` 直接跳过），读档使用档内数值。
