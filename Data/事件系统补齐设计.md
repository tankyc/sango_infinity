## 2. 五个新机制

### 2.1 M1 定时事件队列（ScheduledEventQueue）— 解决 D5

**问题**：基础框架坚持"事件立即结算、不跨回合挂起"，导致官渡、赤壁、夷陵、北伐这类**战役级多阶段事件**无法表达。

**设计**：在 `Scenario` 上挂一个**定时待办队列**，随存档持久化。

```csharp
namespace Sango.Core.Event
{
    /// <summary>
    /// 定时待办项：在指定回合触发某个事件，或直接执行一组效果。
    /// 用于实现跨回合的战役级事件链（如官渡之战分 6 个阶段）。
    /// 随存档持久化，读档后继续生效。
    /// </summary>
    [JsonObject(MemberSerialization.OptIn)]
    public class ScheduledEventItem
    {
        /// <summary>要触发的事件 Id；为 0 时表示只执行 InlineEffects</summary>
        [JsonProperty] public int TargetEventId;

        /// <summary>绝对触发回合数（= 登记时的回合数 + DelayTurns）</summary>
        [JsonProperty] public int FireTurn;

        /// <summary>所属事件链 Id，用于编辑器分组展示与整链取消</summary>
        [JsonProperty] public int ChainId;

        /// <summary>所属事件链的阶段号</summary>
        [JsonProperty] public int Stage;

        /// <summary>登记时继承下来的槽位绑定（对象 Id，避免跨回合后重新绑定出错）</summary>
        [JsonProperty] public Dictionary<string, int> BoundSlotIds;

        /// <summary>取消条件（JSON 序列化的条件树）；每回合检查，成立则丢弃本项</summary>
        [JsonProperty] public string CancelConditionJson;
    }
}
```

`Scenario` 新增字段：

```csharp
/// <summary>定时事件队列：跨回合战役事件的调度表，随存档持久化</summary>
[JsonProperty] public List<ScheduledEventItem> ScheduledEvents = new List<ScheduledEventItem>();
```

`ScenarioEventManager.Update()` 的每回合检查：

```
for each item in Scenario.Cur.ScheduledEvents (倒序遍历):
    if 当前回合 < item.FireTurn: continue
    if CancelConditionJson 成立:
        移除该项；Log.Info($"定时事件 {item.TargetEventId} 因条件不成立被取消")
        continue
    if item.TargetEventId > 0:
        用 item.BoundSlotIds 重建 EventContext → 入播放队列
    else:
        直接执行 InlineEffects
    移除该项
```

**新指令 `Schedule`**：

```jsonc
{ "Op": "Schedule", "Params": {
    "TargetEventId": 4002,            // 或改用 InlineEffects 直接挂一组效果
    "DelayTurns": 3,                  // 3 回合后触发
    "ChainId": 4001,
    "Stage": 2,
    "BindSlots": ["ActionForce", "TargetPerson"],   // 继承哪些槽位的绑定
    "CancelIf": { "Type": "ForceAlive", "Params": { "Slot": "TargetForce" } }
} }
```

**为什么继承 `BoundSlotIds` 而不是继承 `EventContext` 对象**：
跨回合后原 `EventContext` 里的 `SangoObject` 引用可能已失效（武将死亡、部队解散、城市易主）。存 **Id**，在触发时重新解析为对象并做有效性校验，失效则按 `Optional` 策略处理。

### 2.2 M2 事件链（EventChain）— 解决 D5

`EventDefinition` 增加 `Chain` 元信息：

```jsonc
"Chain": {
  "ChainId": 4001,
  "Name": "官渡之战",
  "Stage": 2,
  "StageName": "斩颜良"
}
```

- 编辑器左侧列表按 `ChainId` **折叠分组**，一个战役显示为一行，可展开看各阶段
- 提供"整链重置"（把链上所有事件的 `FireCount` 与 `ScheduledEvents` 清空）
- 提供"整链预览"（按 Stage 顺序列出所有台词与效果）

`ChainId` 分配规则：`4000` 段位给战役链（4001 官渡、4002 赤壁、4003 夷陵、4004 北伐…）。

### 2.3 M3 事件索引与性能（EventIndex）— 解决 D9

**问题**：266 个事件若每次 hook 全量求值条件树，开销不可接受。

**三级索引**：

```csharp
/// <summary>事件索引：加速条件求值，避免每次 hook 遍历全部事件</summary>
public class EventIndex
{
    /// <summary>一级索引：按触发时机分组（最粗粒度，命中率最高）</summary>
    public Dictionary<EventTriggerKind, List<EventDefinition>> byKind;

    /// <summary>二级索引：每个 Kind 内按 EarliestYear 升序排列，用二分裁剪年份区间</summary>
    public Dictionary<EventTriggerKind, int[]> kindYearStarts;

    /// <summary>三级索引：按 ChainId 分组，便于整链操作</summary>
    public Dictionary<int, List<EventDefinition>> byChain;
}
```

**`Trigger.EarliestYear / LatestYear` 作为必填索引键**：
- 编辑器从条件树里的 `TimeRange` / `DateCheck` 自动提取并**校验一致性**（不一致则报校验错误）
- 无日期条件的事件填 `EarliestYear = 0`（表示任何年份都要检查）

**条件求值按 Cost 分级短路**：

```csharp
/// <summary>条件求值开销分级，用于排序后短路求值</summary>
public enum ConditionCost
{
    /// <summary>极廉价：纯内存比较（flag、事件计数、难度）</summary>
    Trivial = 0,
    /// <summary>廉价：单对象属性读取（武将属性、忠诚）</summary>
    Cheap = 1,
    /// <summary>中等：需要遍历某势力的集合（城池数、武将数）</summary>
    Normal = 2,
    /// <summary>昂贵：全场景遍历（距离计算、寻路）</summary>
    Expensive = 3,
}
```

`EventConditionDatabase` 求值时把 `Conditions` 树展平为列表，按 `Cost` 升序排，依次短路。**`ProbabilityCheck` / `RandomChance` 必须排最后**，避免消耗随机数后才因其它条件失败（读档重放一致性问题）。

**预算控制**：`ScenarioVariables` 新增
- `MaxEventEvalPerTurn`（默认 64）：单回合最多求值的事件数
- `MaxEventFirePerTurn`（默认 3）：单回合最多播放的事件数

### 2.4 M4 事件调试面板（UIEventDebugPanel）— 解决 D21

**刚需**。266 个事件没有调试手段等于不可维护。

**功能**：

| 功能 | 说明 |
| --- | --- |
| 事件状态表 | `Id / 名称 / 链 / 状态 / 已触发次数 / 上次触发回合 / 最近一次失败原因` |
| 条件求值明细 | 点开某事件，逐节点显示"条件类型 / 参数 / 求值结果（绿✓红✗）/ 耗时" |
| 性能监视 | 本回合求值了几个事件、总耗时 ms、被预算截断的事件数 |
| 手动操作 | 强制触发 / 重置触发次数 / 禁用本事件 / 跳转到编辑器编辑 |
| 定时队列视图 | 列出 `ScheduledEvents` 中所有待办项（目标事件、剩余回合、继承槽位） |
| 触发历史 | 按回合倒序的事件触发流水 |

**`EventRunState` 扩展**：

```csharp
/// <summary>最近一次触发失败的原因（调试用，不进存档或只保留最近 N 条）</summary>
```

### 2.5 M5 事件密度控制 — 解决 D26

**问题**：191、208、220 年事件扎堆，一次回合开始可能连弹 8 个。

**设计**：

1. **优先级分级**（`EventDefinition.Level`）：

| Level | 行为 |
| --- | --- |
| `Critical` | 必须中断玩家操作，独占演出（历史节点：桃园结义、赤壁、夷陵） |
| `Normal` | 正常弹出对话框（默认） |
| `Ambient` | **不弹窗**，只写入"事件一览"窗口与 `PlayerMessage`（如"某某就任太守"） |
| `Silent` | 完全静默，只结算效果（内政类、数据类） |

2. **每回合上限**：超过 `MaxEventFirePerTurn` 的事件自动降级为 `Ambient`（入"事件一览"，不打断）。

3. **事件一览窗口（UIEventList）**：仿三国志14 的"事件发生"列表，玩家可批量查看本回合发生的所有事件，逐条点开重看演出。

4. **跳过演出**：`Op: SkipAll` 或面板上的"跳过演出"按钮 —— 播放中跳过剩余 `Talk`/`Camera`，**只走 `Effect`**。
