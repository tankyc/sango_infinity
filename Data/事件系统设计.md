# Sango Infinity 剧本事件系统设计文档（基础框架）

> 版本：v1.0（设计稿）
> 日期：2026-09-24
> 参照：三国志14 事件编辑器（イベントエディタ）
> 适用范围：剧本剧情事件（Scenario Event）— 触发条件、演出分镜、玩家选择、世界状态效果、结果情报
>
> **配套文档**
> - `Data/三国历史事件清单与设计洞分析.md` — 266 个三国历史事件全量清单 + D1~D32 设计洞分析（需求池）
> - `Data/事件系统补齐设计.md` — 补齐方案（5 个新机制、27 条指令、60 种条件、70 种效果、官渡之战端到端验收）
>
> **本文范围**：基础框架。它自身可覆盖约 23% 的历史事件（单回合、双势力、无状态依赖的台词类事件）。
> 要做官渡、赤壁、夷陵这类**战役级多阶段事件**，必须叠加《补齐设计》里的 M1 定时事件队列、M2 事件链、M3 索引、M4 调试面板、M5 密度控制。

## 1. 设计目标

### 1.1 目标

用一套**纯数据驱动**的框架，让策划/Mod 作者不写代码就能做出"三国志14 式"的剧本事件：

| 三国志14 编辑器能力 | 本框架对应模块 |
| --- | --- |
| 事件一览 / 事件分类 / 复制 | 事件表（JSON 表 + 编辑器列表） |
| 发生条件（时期、势力、都市、武将、外交、战况） | `EventTriggerDef` + `EventConditionNode`（条件树） |
| 登场人物（谁说话、谁被提到） | `EventActorSlot`（角色槽） |
| 演出（台词、立绘表情、镜头、BGM/SE、图片、等待、点击） | `EventStage` 指令流（Step 列表） |
| 选择肢与分支 | `Choice` + `Label` / `Jump` |
| 结果（效果） | `EventEffectNode`（效果列表） |
| 结果情报（事件后弹出的情报） | `ResultInfo` Step + `PlayerMessage` |
| 触发次数（仅一次 / 可重复） | `once` / `maxFireCount` / `cooldownTurns` |
| 事件优先级 | `priority` + 事件队列 |

### 1.2 硬性约束（必须遵守）

1. **一切数值走配置**：事件涉及的成长/资源数值，一律通过 `GainValueConfig` 的 `GainPlace` 键 + `Scenario.Cur.Variables` 读取，JSON 里**不允许硬编码**成长数值（可指定"用哪个键"）。
2. **不新增游戏主循环**：事件的驱动只允许**订阅 `GameEvent` 的既有 hook**，不得在 `Scenario.Run()` 里插自定义调用。
3. **回合制节奏**：事件效果按"一年 36 回合"核算，效果语义必须是"一次性结算"，不做跨回合挂起。
4. **中文注释不低于 30%**，符合 C# / Unity 注释规范。
5. **外部数据 JSON**，使用 `TKNewtonsoft.Json`；`System.Math`、`UnityEngine.Vector3`、`System.IO.Path` 等一律写全命名空间。

## 3. 总体架构

```
┌─────────────────────────────────────────────────────────────────────┐
│  编辑器层  UIEventEditor / EventValidator / EventSerializer          │
│  (游戏内 uGUI 窗口，仿 MapEditor 形态；读写 JSON)                     │
└───────────────────────────────┬─────────────────────────────────────┘
                                │ JSON
┌───────────────────────────────▼─────────────────────────────────────┐
│  数据层   EventDefinition / EventTriggerDef / EventActorSlot         │
│           EventConditionNode / EventStage / EventEffectNode          │
│           (纯数据，[JsonObject(MemberSerialization.OptIn)])           │
└───────────────────────────────┬─────────────────────────────────────┘
                                │ 索引
┌───────────────────────────────▼─────────────────────────────────────┐
│  调度层   ScenarioEventManager (Singleton + GameSystem)              │
│  订阅 GameEvent hook → 收集候选事件 → 优先级排序 → 条件求值          │
│  → 角色槽绑定 → 入事件队列 → 交 EventRunner 播放                      │
│  维护 EventRunState（已触发次数、冷却、旗标）← 随存档持久化           │
└───────────────────────────────┬─────────────────────────────────────┘
                                │ 播放
┌───────────────────────────────▼─────────────────────────────────────┐
│  执行层   EventRunner (GameSystem，入栈独占输入)                      │
│  EventContext（槽位绑定表 + 自定义变量 + 选项结果 + 分支历史）        │
│  指令指针 PC 驱动 Step 状态机：Talk/Camera/Bgm/Choice/Label/Jump…    │
│  效果节点经 EventEffectFactory 创建并 Execute(ctx)                   │
└───────────────────────────────┬─────────────────────────────────────┘
                                │ 调用
┌───────────────────────────────▼─────────────────────────────────────┐
│  表现层   GameDialog / PlayerChoice / Window / RenderEvent / 相机     │
│           PlayerMessage（结果情报）                                   │
└─────────────────────────────────────────────────────────────────────┘
```

**关键分工**

- `ScenarioEventManager` 只做"**要不要发生、什么时候发生、谁参与**"，**不做演出**。
- `EventRunner` 只做"**怎么演、演完算账**"，**不做触发判定**。
- 条件与效果都是**可注册的插件**：新条件/新效果只需在对应 `Init()` 里 `Register("名字", 创建器)`，编辑器自动出现在下拉列表（通过反射枚举 `CreateMap`）。

## 4. 数据模型

### 4.1 表结构总览

一个事件表文件 = 一个 JSON 数组，数组元素为一个事件定义：

```
Build/Content/Data/ScenarioEvent/<分类>/<序号>_<名称>.json   ← 内置
<persistentDataPath>/CustomEdit/Data/ScenarioEvent/*.json    ← 玩家自定义
<mod目录>/Data/ScenarioEvent/*.json                          ← Mod 覆盖/追加
```

加载顺序：内置 → 自定义 → Mod（后加载者按 `Id` 覆盖前者，并在编辑器里标注来源）。

### 4.2 EventDefinition（事件定义）

```jsonc
{
  "Id": 1001,                       // 全局唯一，建议按分类分段（1000 神话/史实、2000 通用、3000 Mod）
  "Name": "桃园结义",                // 编辑器显示名
  "Category": "History",             // History/Common/Person/Troop/Diplomacy/Tutorial/Mod
  "Description": "刘关张结为兄弟。", // 供编辑器查看，不显示给玩家
  "Enabled": true,
  "Priority": 100,                   // 越大越先播放；同优先级按 Id 升序
  "Interrupt": true,                 // true=可打断玩家当前操作；false=只在回合空闲点检查

  "Trigger": { ... },                // §4.3 触发设定
  "Slots":   [ ... ],                // §4.4 角色槽
  "Conditions": { ... },             // §4.5 发生条件（条件树，根节点）
  "Stages":  [ ... ],                // §4.6 演出指令流
  "ResultInfo": { ... },             // 可选：事件结束后的结果情报（§4.7）
  "Variables": { "FavorLevel": 0 }   // 事件私有变量初值（每局游戏独立）
}
```

### 4.3 EventTriggerDef（触发设定）

```jsonc
"Trigger": {
  "Kind": "CityFall",          // 触发时机，见下表
  "Scope": "AnyForce",         // AnyForce / PlayerForce / SpecificForce / SpecificCity
  "ScopeId": 0,                // Scope 为 Specific 时使用
  "JobTypes": ["Searching"],   // 仅 Kind=JobFinished 时生效，过滤 MissionType/CityJobType
  "DelayTurns": 0,             // 条件满足后延迟 N 回合再播放（用于"事件余波"）
  "Once": true,                // 只触发一次
  "MaxFireCount": 0,           // 0=不限；>0 时受此上限约束（三顾茅庐 = 3）
  "CooldownTurns": 0,          // 两次触发间隔回合数
  "Chance": 100                // 满足条件后的触发概率（%）
}
```

> `Kind = "JobFinished"` 时，`GameEvent.OnPersonActionOver` **只带 `Person` 一个参数**，无法区分是搜索、内政还是登用。因此触发层必须按 `person.missionType`（`MissionType` 枚举）做二次判断，`JobTypes` 就是这层过滤条件。若需要更精确的"搜索完成"钩子，可改订阅 `GameEvent.OnCityJobSearchingWild`。

`Kind` 枚举（与 `GameEvent` hook 一一对应，由 `ScenarioEventManager.Init()` 统一订阅）：

| Kind | 接入 hook | 注入的"事件实体"（供 Slot 引用） |
| --- | --- | --- |
| `ScenarioStart` | `OnScenarioStart` | — |
| `TurnStart` / `TurnEnd` | `OnTurnStart` / `OnTurnEnd` | — |
| `ForceTurnStart` | `OnForceTurnStart` | 当前力 `Force` |
| `MonthStart` / `SeasonStart` / `YearStart` | `OnMonthStart` / `OnSeasonUpdate` / `OnYearUpdate` | — |
| `CityFall` | `OnCityFall` | 陷落城 `City`、原势力、攻方势力 |
| `CityOwnerChange` | `OnCityFall` | 同上（语义更宽，含易主非陷落） |
| `PersonCaptured` | `OnPersonCaptured` | 被俘武将 `Person`、俘获势力 |
| `PersonExecute` | `OnPersonExecute` | 处决武将 |
| `PersonEscape` | `OnPersonEscape` | 逃脱武将 |
| `PersonJoinForce` | `OnPersonChangeBelongCity` + 校验 `BelongForce` 变化 | 武将、势力 |
| `ForceFall` | `OnForceFall` | 灭亡势力 |
| `TroopCreated` / `TroopDestroyed` | `OnTroopCreated` / `OnTroopDestroyed` | 部队 |
| `BuildingComplete` | `OnBuildingComplete` | 建筑 |
| `DiplomacyAlliance` / `DiplomacyDeclareWar` / `DiplomacySendGift` / … | `OnDiplomacy*` | 双方势力 |
| `DuelFinished` / `DebateEnd` | `OnDuelFinished` / `OnDebateEnd` | 双方武将 |
| `TroopEnterCell` / `TroopLeaveCell` | `OnTroopEnterCell` / `OnTroopLeaveCell` | 移动的部队（三英战吕布的"接敌瞬间"用这个） |
| `JobFinished` | `OnPersonActionOver`（**必须**用 `JobTypes` 过滤） | 执行武将、所在城池 |
| `DateReach` | `OnDayUpdate` | — （配合条件树里的 `TimeRange`） |
| `ManualCall` | 无（由其它事件 / 剧本脚本 `CallEvent` 调用） | — |

> **注意**：`GameEvent` 中不存在 `OnCityCaptured` / `OnPersonDied`，对应语义分别是 `OnCityFall` 与 `OnPersonExecute`。实现时不要臆造 hook。

### 4.4 EventActorSlot（角色槽）

角色槽是 RTK14"登场人物"的对应物，也是旧 `Action*/Target*` 双槽的**超集**。JSON 里用 `ActionXxx` / `TargetXxx` 作为槽位 key，即可**兼容旧数据**。

```jsonc
"Slots": [
  {
    "Key": "ActionForce",          // 文本占位符与效果里引用的名字
    "Type": "Force",               // Force/Corps/City/Person/Troop/Skill/Cell/Building
    "Source": "PlayerForce",       // 取值来源，见下表
    "SourceArg": null,             // 例如 Fixed 时的 Id、Attribute 时的属性名
    "Filters": { ... },            // 过滤条件（Source 为 Random/Filter 时生效）
    "Optional": false,             // true=找不到也不阻断事件（槽位置空）
    "Label": "主角势力"             // 编辑器显示名
  },
  {
    "Key": "ActionCounsellor",
    "Type": "Person",
    "Source": "ForceBestPerson",
    "SourceArg": "Intelligence",   // 智力最高者当军师
    "Filters": { "Belong": "InForce", "Alive": true },
    "Optional": false,
    "Label": "军师"
  },
  {
    "Key": "TargetPerson",
    "Type": "Person",
    "Source": "EventEntity",       // 本次 hook 注入的对象（如被俘武将）
    "SourceArg": "Person",
    "Optional": true,
    "Label": "被俘武将"
  }
]
```

`Source` 枚举：

| Source | 含义 | SourceArg |
| --- | --- | --- |
| `Fixed` | 指定对象 Id（编辑器中下拉选择） | Id |
| `EventEntity` | hook 注入的对象 | 类型名，如 `"Person"` / `"City"` |
| `PlayerForce` | 玩家操作的势力 | — |
| `ForceGovernor` / `ForceCounsellor` | 势力君主 / 军师 | — |
| `ForceBestPerson` | 势力内某属性最高者 | `Force/Command/Intelligence/Politics/Glamour` |
| `ForceRandomPerson` | 势力内随机武将 | — |
| `CityGovernor` / `CityRandomPerson` | 城市太守 / 城内随机武将 | — |
| `PlayerMainCity` | 玩家势力主城 | — |
| `NeighborForce` / `NeighborCity` | 事件实体的邻接势力/城市 | — |
| `TroopOfPerson` | 指定武将所在的部队 | `"PersonSlotKey"` |
| `ForceBestTroop` | 势力内兵力最多的部队 | — |
| `NeighborTroop` | 指定槽位部队的相邻敌方部队 | `"TroopSlotKey"` |
| `DerivedOfSlot` | 由另一槽位派生（如"某人的所属势力"） | `"SlotKey.BelongForce"` |
| `ScenarioVariable` | 由剧本变量指定 | 变量名 |

> **重要：部队（Troop）不能用 `Fixed` + Id 绑定。** 部队是运行时创建/销毁的对象，其 Id 每局游戏都可能不同，剧本 JSON 里写死 Id 必然失效。所有 `Type = "Troop"` 的槽必须使用 `TroopOfPerson` / `ForceBestTroop` / `NeighborTroop` / `EventEntity` 这类**描述性来源**。城市、势力、武将、建筑是剧本静态对象，可以安全使用 `Fixed` + Id。

`Filters` 通用字段：`Alive`、`Belong`（`InForce`/`InCity`/`Free`）、`Gender`、`AttributeRange{Attr,Min,Max}`、`LoyaltyRange`、`SkillIdList`、`ExcludeSlotKeys`（互斥，避免同一人占两个槽）、`SameForceAsSlot`。

**绑定失败策略**：任一 `Optional=false` 的槽绑定失败 → 整个事件**放弃触发**（不改状态、不计次数、不消耗随机数）；`Optional=true` 的槽绑定失败 → 槽为空，占位符替换为 `""`，引用该槽的效果节点被跳过并打 `Log.Warning`。

**槽位解析是确定性的**：同一次触发内，`RandomPersonInForce` 等随机来源使用 `GameRandom`，并按 `EventContext` 缓存结果，保证同一事件内多次引用同一槽得到同一对象。

### 4.5 EventConditionNode（发生条件）

条件树，复用 `Condition.CreateMap` 的注册范式；新增的条件注册在 `EventConditionFactory.Init()`。

```jsonc
"Conditions": {
  "Type": "and",
  "Children": [
    { "Type": "TimeRange", "Params": { "YearMin": 200, "YearMax": 208, "MonthMin": 1, "MonthMax": 12 } },
    { "Type": "ForceAlive", "Params": { "Slot": "ActionForce" } },
    { "Type": "ForceCityCount", "Params": { "Slot": "ActionForce", "Min": 3 } },
    { "Type": "ForceHasCity", "Params": { "Slot": "ActionForce", "CityId": 12 } },
    { "Type": "PersonBelongCheck", "Params": { "Slot": "ActionCounsellor", "Belong": "InForce", "LoyaltyMin": 90 } },
    { "Type": "PersonNotUsedBySlot", "Params": { "Slot": "ActionCounsellor", "Exclude": ["TargetPerson"] } },
    { "Type": "RelationCheck", "Params": { "ForceA": "ActionForce", "ForceB": "TargetForce", "Min": 60 } },
    { "Type": "VarCompare", "Params": { "Var": "FavorLevel", "Op": ">=", "Value": 3 } },
    { "Type": "FlagCheck", "Params": { "Flag": "YellowTurbanDone", "Expect": true } },
    { "Type": "EventFired", "Params": { "EventId": 1000, "Expect": false } },
    { "Type": "RandomChance", "Params": { "Percent": 30 } },
    { "Type": "or", "Children": [
        { "Type": "PlayerForceCheck", "Params": {} },
        { "Type": "DifficultyCheck", "Params": { "Min": 3 } }
    ]}
  ]
}
```

**事件专用新增条件清单**（Phase 1 必做）：

| Type | 参数 | 说明 |
| --- | --- | --- |
| `TimeRange` | `YearMin/YearMax/MonthMin/MonthMax/Season` | 时期限定 |
| `ForceAlive` | `Slot` | 势力存在且未灭亡 |
| `ForceCityCount` | `Slot`, `Min/Max` | 城池数量（含关港可加 `IncludeGatePort`） |
| `ForceHasCity` | `Slot`, `CityId` | 拥有指定城市（支持 Id 列表） |
| `ForceHasPerson` | `Slot`, `PersonId` | 麾下有指定武将 |
| `ForceResourceCheck` | `Slot`, `GoldMin/FoodMin/TechniqueMin` | 资源 |
| `PersonBelongCheck` | `Slot`, `Belong`, `ForceSlot`, `CitySlot` | 所属 |
| `PersonStateCheck` | `Slot`, `State`（Alive/Dead/Captive/Free/Idle） | 状态 |
| `PersonAttributeCheck` | `Slot`, `Attr`, `Min/Max` | 属性（须走 `Command/Strength/Intelligence/Politics/Glamour` 读取） |
| `PersonLoyaltyCheck` | `Slot`, `Min/Max` | 忠诚 |
| `PersonNotUsedBySlot` | `Slot`, `Exclude` | 槽位互斥 |
| `RelationCheck` | `ForceA`, `ForceB`, `Min/Max` | 外交关系值 |
| `AllianceCheck` / `TruceCheck` | `ForceA`, `ForceB`, `Expect` | 同盟/停战 |
| `VarCompare` | `Var`, `Op`, `Value` | 事件私有变量 |
| `ScenarioVarCompare` | `Var`, `Op`, `Value` | 剧本变量（`Scenario.Cur.Variables`） |
| `FlagCheck` | `Flag`, `Expect` | 事件旗标 |
| `EventFired` | `EventId`, `Expect` | 事件触发史 |
| `RandomChance` | `Percent` | 概率 |
| `PlayerForceCheck` | — | 是否玩家势力 |
| `DifficultyCheck` | `Min/Max` | 难度 |
| `DateCheck` | `Year/Month/Day` 精确或区间 | 精确日期 |
| `CityAttributeCheck` | `CitySlot`, `Attr`, `Min/Max` | 城市财产/兵力/治安/耐久 |
| `TroopStateCheck` | `Slot`, `TroopMin` 等 | 部队状态 |
| `FireCountCompare` | `Op`, `Value` | **本次是第几次触发**（`EventContext.fireCount` 为 1-based）。三顾茅庐靠它分流三次不同演出 |
| `EventFiredCountCompare` | `EventId`, `Op`, `Value` | 别的事件已触发几次 |
| `TroopExists` | `Slot` | 部队存在且未被消灭 |
| `TroopDistanceCheck` | `SlotA`, `SlotB`, `MinDistance/MaxDistance` | 两部队距离（三英战吕布用；可复用已有 `DistanceCheck`） |
| `ForceHasTroop` | `Slot`, `TroopSlot` | 势力拥有指定部队 |
| `CityHasWildPerson` | `CitySlot`, `PersonSlot` | 在野武将是否在该城（三顾茅庐用） |
| `PersonVisible` | `Slot`, `Expect` | 武将是否已被发现（`PersonStateType.Invisible` 判定） |
| `PersonIsGovernorOf` | `Slot`, `ForceSlot` | 是否为某势力君主 |
| `PersonMissionCheck` | `Slot`, `MissionType` | 武将当前任务类型（`MissionType` 枚举） |
| `and` / `or` / `andList` / `orList` | `Children` | 逻辑组合（复用已有） |

> 所有 `Params` 的数值字段支持**表达式引用**（§4.8），如 `"Min": "$ActionCity.gold * 2"`，便于"按当前局势"判定。

### 4.6 EventStage（演出指令流）

`Stages` 是一个**线性指令数组** + `Label`/`Jump` 形成的分支，等价于一份"剧本脚本"。相比树结构，线性列表在编辑器里可直接上下拖拽，且天然支持"跳到某段"。

  { "Op": "Talk", "Params": {
      "Slot": "ActionCounsellor",
      "Style": "ClickPersonSay",      // 映射 GameDialog.DialogStyle
      "Lines": [
        { "Text": "{:ActionForce}大人，{:TargetPerson}已被我军擒获。", "Face": "normal", "Sound": 101 },
        { "Text": "应该如何处置？", "Face": "serious" }
      ]
    }
  },

  { "Op": "Choice", "Params": {
      "Options": [
        { "Text": "招降", "Next": "recruit", "Conditions": { "Type": "PersonBelongCheck", "Params": { "Slot": "TargetPerson", "LoyaltyMin": 0 } } },

#### 指令（Op）清单

| Op | Params | 说明 | 落地实现 |
| --- | --- | --- | --- |
| `Talk` | `Slot/Style/Lines[{Text,Face,Sound,Bgm}]/TalkEnd` | 台词（支持多句链路） | `GameDialog.OpenTalk` |
| `TalkWindow` | `Text` | 纯文本框（旁白） | `GameDialog.Open(DialogStyle.Window,…)` |
| `Choice` | `Options[{Text,Next,Conditions,Effects}]` | 选择肢；`Next` 为目标 Label | `PlayerChoice.Start` |
| `Effect` | `Effects[]` | 世界状态结算（可放任意位置） | `EventEffectFactory` |
| `Duel` | `ChallengerSlot`, `ChallengedSlot`, `ForceAccept`, `AsEvent`, `Next` | **强制发起事件单挑**（三英战吕布） | `DuelChallengeFlow.Request(troopA, troopB, Source.GameEvent, forceAccept)` |
| `Battle` | `SlotA`, `SlotB` | 强制发起部队交战（Phase 3，需确认入口） | 部队战斗流程 |
| `Camera` | `Slot/X/Y/Zoom/Duration/Reset` | 镜头移动 | 相机控制器 |
| `Bgm` / `Se` / `Voice` | `Id/FadeIn` | 音频 | 音频管理器 |
| `Window` | `WindowName/Args` | 打开任意 UI 窗口（如势力情报图） | `Window.Instance.Open` |
| `Message` | `Text/Slot/X/Y` | 玩家消息（结果情报逐条弹） | `PlayerMessage.AddTextMessage` |
| `Wait` | `Seconds` 或 `WaitClick` | 等待 | `EventRunner.Update` 计时 |
| `Label` / `Jump` | `Name` / `Target` | 分支跳转 | 指令指针 |
| `Branch` | `Conditions`, `Target`（条件成立则跳） | 条件跳转（无 UI） | 指令指针 |
| `SetVar` | `Var/Op/Value` | 事件私有变量运算 | `EventContext` |
| `SetFlag` | `Flag/Value` | 事件旗标（跨事件、进存档） | `EventRunState` |
| `CallEvent` | `EventId` / `EventTag` | 嵌套调用另一事件（串场） | 递归 `EventRunner`（限深 3 层） |
| `End` | — | 结束（缺省则跑完自动结束） | — |

> **为什么不用 `RenderEvent` 队列**：`RenderEvent` 是表现层池化播放器，适合"插入一段独立演出"，但**不承载分支逻辑与失败回滚**。因此 `EventRunner` 自持状态机（`GameSystem.Update()` 驱动），只在需要"插入一段纯表现"时创建 `RenderEvent`。

### 4.8 表达式与占位符

| 语法 | 场景 | 说明 |
| --- | --- | --- |
| `{:SlotKey}` | 任何字符串参数 | 替换为槽位对象 `Name`（复用现有 `ScenarioEvent.FormatContent` 的解析器，改为读 `EventContext`） |
| `{:SlotKey.Attr}` | 任何字符串参数 | 取属性，如 `{:ActionCity.gold}`、`{:TargetPerson.Command}` |
| `{:var:Name}` | 任何字符串参数 | 事件私有变量 |
| `{:svar:Name}` | 任何字符串参数 | 剧本变量 |
| `$SlotKey.Attr` | **数值参数**（条件/效果的 `Value`/`Min`/`Max`） | 数值求值 |
| `#VarName` | 数值参数 | 事件私有变量求值 |
| `{ "GainPlace": "X" }` | 数值参数 | **取成长配置表的值**（强制走 `GainValueConfig.TableOf`，禁止硬编码） |

数值求值器 `EventValue.Eval(object raw, EventContext ctx)`：
- `int/long/double` → 直接返回
- `string` → 按上表语法解析（先 `$`/`#`/`{:...}`，否则 int 解析，失败返回 0 并 `Log.Warning`）
- `object`（含 `GainPlace`） → 查 `GainValueConfig`，按 `Range` 类型 roll 或按 `Fixed/Rate` 取值

> 这解决了硬性约束 1：**"忠诚 +5" 必须写成 `{"GainPlace":"RecruitLoyalty"}`**，实际值由 `Scenario.Cur.Variables` 的 `GainValueConfig` 决定，且可在剧本设置界面"成长资源获取"分区调整。

## 5. 运行时流程

### 5.1 触发判定（发生在 hook 回调内，同步、轻量）

```
GameEvent hook 触发
  └─ ScenarioEventManager.OnHook(kind, eventEntity)
       ├─ 若事件队列已有事件在播放 → 新候选事件入"待播队列"（不丢，回合末统一处理）
       ├─ 取该 kind 的候选事件列表（索引：Dictionary<EventTriggerKind, List<EventDefinition>>）
       ├─ 过滤：Enabled / Once 已触发 / MaxFireCount / Cooldown / Scope 不匹配 / Chance 未中
       ├─ 条件树求值（Condition.Check，需构造 EventConditionDatabase）
       ├─ 角色槽绑定（失败→丢弃该候选）
       ├─ 通过者入候选池
       └─ 排序（Priority 降序、Id 升序）→ 逐个入播放队列
```

**必做细节**

- 候选事件在**同一次 hook 内**只触发一个最小单元：第一个通过的事件入队后，其余候选标记为"待下一回合检查"，避免一回合连播 5 个事件。
- `TurnStart` 检查 + 播放放在 `GameEvent.OnTurnStart` **之后一帧**（`ScenarioEventManager` 的 `Update` 里），确保所有系统已完成回合初始化。
- 事件播放期间 `Scenario.Run()` 的回合推进**必须阻塞**（见 §5.2）。
- 候选筛选使用 `GameRandom`，但**不得在筛选阶段消耗随机数**（否则读档重放会不一致）——`RandomChance` 使用事件的 `(EventId, TurnCount)` 派生种子。

### 5.2 播放（EventRunner）

```
ScenarioEventManager 从队列取 EventDefinition
  └─ 创建 EventRunner(definition, context)
       ├─ runner.Push()          // 入 GameSystemManager 栈，独占输入
       ├─ GameEvent.DialogShow 期间玩家不可操作
       ├─ Update() 逐帧推进指令指针：
       │     Talk    → GameDialog.OpenTalk(..., 回调 = PC++)
       │     Choice  → PlayerChoice.Start(options, 回调 = PC = LabelIndex(next))
       │     Effect  → 立即结算（同步）
       │     Wait    → 计时/等待点击
       │     Label/Jump/Branch → 立即改 PC
       │     End     → Back()
       └─ OnDestroy → 写回 EventRunState（FireCount++ / LastFireTurn / Flags / Vars）
                     → 若队列非空，继续下一个事件
```

**异常兜底**：任一指令执行抛异常 → 捕获、`Log.Error`、跳过该事件、**不写回状态**（等价于"该事件未发生"），并解锁输入。禁止让异常导致玩家永久卡死。

### 5.3 时序（典型回合）

```
TurnStart
  → GameEvent.OnTurnStart（各系统初始化）
  → ScenarioEventManager.Update：检查 TurnStart 类事件 → 若有 → 播放（阻塞）
  → RunForces
      → Force.Run → GameEvent.OnForceTurnStart
          → ScenarioEventManager：检查 ForceTurnStart 类事件 → 播放（阻塞）
  → TurnEnd → 检查 TurnEnd 类事件
  → IncreaseDate → 触发 OnMonthStart/OnSeasonUpdate/OnYearUpdate → 检查对应事件
```

**关键约束**：事件若在 `Force.Run()` 中途触发（如 `CityFall`、`JobFinished`），播放必须是**同步阻塞**的（在 hook 回调内直接 `runner.Push()` 并靠 `Update` 推进），否则会出现"势力在事件演出期间继续行动"的状态错乱。这一点需要在实现时确认 `Scenario.Run()` 是否每帧 `yield`（若已是协程/状态机则天然支持）。

### 6.3 交互要点

| 需求 | 设计 |
| --- | --- |
| 新建事件 | 自动分配 Id（当前最大 Id +1，按分类段位取整） |
| 复制事件 | 深拷贝 + 重新分配 Id + 名称加"(副本)" |
| 拖拽排序 | 仅影响 JSON 数组顺序，不影响优先级（优先级显式配置） |
| 条件编辑 | 树形控件；条件类型下拉 = 反射枚举 `Condition.CreateMap`，选择后按条件类声明的参数自动生成表单 |
| 效果编辑 | 同上，反射枚举 `EventEffectBase.CreateMap` |
| 角色槽引用 | 所有引用对象的输入框都是**下拉选择**（势力/城市/武将/部队按当前剧本实时列出），不允许手填 Id |
| 占位符插入 | 台词/文本输入框旁有"插入占位符 ▾"，列出全部槽位与变量 |
| 数值字段 | 提供双模式：固定值 / 引用 `GainPlace` 键（下拉列出全部 `GainPlace` 枚举） |
| 分支可视化 | 选中 `Choice` 时高亮各选项的 `Next` Label 行；`Jump` 显示为带箭头的行 |
| 校验 | 保存/试跑前自动跑：断链 Label、空槽位 Key 重复、未绑定槽引用、效果参数缺失、`Optional` 槽被效果强制引用、数值硬编码检测（效果里出现裸数字且该参数标注了"需走 GainPlace"） |
| 试跑 | Phase 2：**只演出不结算**（效果节点仅 `Log.Info` 打印"将执行 X"，并暂停等待确认）。Phase 3：沙盒快照 + 一键回滚 |
| 存盘 | 写入 `CustomEditRootPath/Data/ScenarioEvent/*.json`；若目标事件来源是内置/Mod，弹"另存为覆盖副本"确认 |
| 参数说明 | 每个条件/效果类通过特性提供中文名与说明（见 §8.1），编辑器据此显示 tooltip |

### 6.4 编辑器数据流

```
加载：内置/自定义/Mod 三源 JSON → EventDefinition 列表（带 SourceTag）
编辑：内存中的 EventDefinition 对象
保存：按 SourceTag 分文件序列化；自定义源直接覆盖；内置/Mod 源另存到 CustomEdit 目录
试跑：直接取内存对象 → 构造 EventContext（Role 手动指定或自动绑定）→ EventRunner
```

## 7. 与外交事件系统的关系

`DiplomacyEventManager` 的"使者来访 / 同盟请求 / 割让"等，本质是**触发时机为 `DiplomacyXxx`、效果为外交操作**的普通事件。设计上：

- 短期（Phase 1~3）：两套并存，互不干扰。`DiplomacyEventManager` 的 JSON（`Data/DiplomacyEvent/`）**继续沿用现结构**，只在必要时接线。
- 长期（Phase 4）：为 `DiplomacyEventManager` 提供"转换器"，把 `DiplomacyEvent` JSON 转成 `EventDefinition`（`Trigger.Kind = DiplomacyXxx`），统一到本框架，删除旧管理器。

## 11. 边界情况与风险

| 风险 | 处理 |
| --- | --- |
| 事件播放中玩家点"存档" | 播放期间禁用存档按钮；档中若存在"未完成事件"则读档时丢弃并解锁输入 |
| 读档重放导致事件重复触发 | `EventRunState` 进存档；`RandomChance` 用 `(EventId, TurnCount)` 派生种子，不用全局随机流 |
| 一回合触发多个事件 | 同 hook 内只触发 1 个；其余排到下一回合 |
| 事件效果导致势力灭亡 / 武将被处决 | 效果执行后检查 `Force.IsAlive` / `Person` 状态，若槽位对象在演出中失效 → 后续引用该槽的指令跳过并 `Log.Warning`（不崩） |
| 槽位绑定到的对象在演出中被 AI 消灭 | 同上：`EventContext.GetSlot()` 每次返回前做有效性校验 |
| `CallEvent` 递归死循环 | 限制嵌套深度 3 层；超过则 `Log.Error` 并终止 |
| 事件播放打断玩家操作 | `Interrupt=false` 的事件只在"玩家无操作"的空闲点（回合开始/势力回合开始）触发；`Interrupt=true` 才可中途插入 |
| 台词过长超出对话框 | 编辑器校验台词长度上限；运行时按 `UIDialog` 现有换行规则处理 |
| 条件/效果参数写错名字 | 反序列化时用 `JObject` 宽松读取 + 校验器提示，不直接抛 `JsonSerializationException` |

**设计要点**：

1. **`FireCountCompare` 是"重复触发型事件"的核心**。`EventContext.fireCount` 定义为**本次触发的序号（1-based）**，第一次播放 = 1、第二次 = 2、第三次 = 3。配合 `Branch` 即得到"三次不同演出"，无需三份 JSON。
2. **`MaxFireCount: 3` 用完即止**。第三次若选"容后再议"，机会用尽，诸葛亮不会通过本事件加入——这是符合直觉的设计。若要"允许无限次但只成功一次"，则改为 `MaxFireCount: 0` + 用 `FlagCheck(ThreeVisitsDone)` 控制。
3. **诸葛亮必须预先置于隆中的在野名单**（`City.wildPersons` + `CurrentCity`）。这是**剧本初始数据**的职责。当前在野武将挂在城市上、没有独立格子坐标，所以"隆中"必须是一座城/港/关；若非要"隆中某格"，需引擎新增按格子挂武将的表示（见 §14）。
4. `PersonSetVisible` 用于把初始 `PersonStateType.Invisible`（未发现）的诸葛亮变为可见，否则玩家在探索前看不到他。
