# 补给队出征条件

> 入口：`CityAI.AIMakeSupplyTroop(city, scenario)`
> 全部阈值可在 `Data/Common/AIConfig.json` 调整。

---

## 一、兵装相关（本轮新增）

### 1. 兵装换算规则

与部队组建**完全一致**：兵种 `costItems` 形如 `[兵装种类, 每千人消耗]`，例如枪兵 `[2, 1000]`
表示每 1000 兵消耗 1000 件枪 —— 即 **1 件兵装装备 1 名士兵**。

```
ItemStore.CheckItemEnough:  need  = costN * number / 1000   // 1000 * 13000 / 1000 = 13000
ItemStore.CheckCostMin:     have  = GetNumber(kind) * 1000 / costN  // 3000 * 1000 / 1000 = 3000
```

| 类别 | `ItemStoreKindType` | 是否计入"可装备兵力" |
|---|---|---|
| 枪 / 戟 / 弩 | 2 / 3 / 4 | ✅ 通用兵装 |
| 战马 | 5 | ✅ 通用兵装 |
| 冲车 / 投石 | 6 / 7 | ❌ 攻城器械，不装备普通部队 |
| **船** | 8 | ⚠️ **单独判定**（见下） |

```
可装备兵力上限 = 枪 + 戟 + 弩 + 战马            （1:1）
若需走水路   → 再取 min(上限, 船数量)            （同样 1:1）
```

> ⚠️ 曾误写成"兵装数 × 1000"，等于把门槛放宽了 1000 倍，
> 导致 13000 兵配 3000 兵装也能出征 —— 已修正为 1:1。

### 2. 出征条件：总兵装能装备随队兵力

```csharp
bool needBoat = needy.IsInWater || city.IsPort();   // 目标在水中 或 本城为港口
int affordable = GetAffordableTroops(city, needBoat);
if (affordable < supplyMinCarryTroops)   // 默认 3000
    return true;                          // 兵装不足以保障最低出征规模 → 取消
if (carryTroops > affordable)
    carryTroops = affordable;             // 否则缩减到可装备规模
```

**行为**：
1. 兵装足够 → 按原计划出征
2. 兵装不够 → **缩减随队兵力**到可装备量
3. 可装备量低于 `supplyMinCarryTroops`（默认 **3000**）→ **取消出征**

### 2.1 兵装 : 兵力 = 1 : 1（随队配比）

```csharp
int landItems = GetAffordableTroops(city, false);
if (carryTroops > landItems) carryTroops = landItems;

// 按"所需 / 现有"折算抽取比例
int part = Math.Min(100, Math.Max(1, carryTroops * 100 / landItems));
ItemStore carryItems = SplitSupplyItems(city, part);

// 逐类取整可能抽少 → 按实物缩减兵力，保证不低于 1:1
if (carryItems.TotalNumber < carryTroops)
    carryTroops = carryItems.TotalNumber;

if (carryTroops < supplyMinCarryTroops)
{
    ReturnItems(city, carryItems);   // 取消出征，兵装原样退回城市
    return true;
}
```

**效果**：带多少兵就配多少兵装，不再出现"13000 兵只带 3000 兵装"。

### 3. 船的需求（单独判定）

船属**水军装备**，不能用陆地兵装替代，因此：

- **走水路时**（目标部队在水中，或本城为港口）：船只数量必须**单独**满足 `carryTroops / 1000`
- 判定式为 `min(陆地兵装额度, 船只额度)`，任一不足都会限制出征规模

### 4. 携带兵装时排除船与器械

原实现直接 `city.itemStore.Split(10)`，会把**船只与攻城器械一并搬走**。现改为 `SplitSupplyItems()`：

```csharp
/// 只抽取通用兵装（枪 / 戟 / 弩 / 战马）
///   · 不含船只 —— 需保留给水军组建
///   · 不含器械 —— 属攻城装备，非前线补给物资
public static ItemStore SplitSupplyItems(City city, int part)
```

抽取比例按「随队兵力 / 城市通用兵装」动态折算，保证 1:1。

## 二、前线部队的兵装比

### 待补给判定（`CollectNeedyTroops`）

满足**任一**即视为需要补给：

| 条件 | 判定 |
|---|---|
| 缺粮 | `food ≤ 0` 或 `food < troops × supplyFoodThresholdFactor` |
| 兵力缺口 | `troops < MaxTroops / 2` |
| **兵装不足**（新增） | 兵装覆盖率 < `supplyNeedyItemPercent`（默认 **50%**） |

### 兵装覆盖率计算（`IsItemShortage`）

```
所需量 = ceil(troops / 1000)
持有量 = 枪 + 戟 + 弩 + 战马 + 船
覆盖率 = 持有量 / 所需量
覆盖率 < 50%  →  兵装不足
```

> 注意：此处**包含船**。判断"前线部队自身装备是否齐备"时，水军部队的船也是其装备的一部分。

## 三、完整出征条件汇总

按代码执行顺序：

| # | 条件 | 不满足时 |
|---|---|---|
| 1 | 势力存在（`mBelongForce != null`） | 返回 |
| 2 | 军团未禁止运输（`TransportDisable != 1`） | 返回 |
| 3 | 空闲武将 ≥ 1 | 返回 |
| 4 | 城池兵力 ≥ `supplyMinCityTroops`（20000） | 返回 |
| 5 | 城池粮草 ≥ `supplyMinCityFood`（60000） | 返回 |
| 6 | 本城已派补给队 < `supplyMaxPerCity`（1） | 返回 |
| 7 | 附近待补给友军 ≥ `supplyMinNeedyTroops`（3） | 返回 |
| 8 | 运输兵种可用（`GetTransportType` 非空） | 返回 |
| 9 | 推荐武将非空 | 返回 |
| 10 | **总兵装能装备随队兵力（含船的单独特判定）** | 缩减兵力，仍不足则返回 |
| 11 | 可装备兵力 ≥ `supplyMinCarryTroops`（3000） | 返回 |

出征后携带：
- 兵力 = `min(城池兵力/2, supplyTroopAmount, 兵装可支撑量)`
- 粮草 = `兵力 × 每兵粮耗 × supplyFoodTurnCount`（受 `supplyFoodAmount` 与城池 2/3 约束）
- 兵装 = `SplitSupplyItems(city, part)`（**仅通用兵装**，数量与兵力 1:1）

## 四、新增配置

| 配置项 | 默认 | 作用 |
|---|---|---|
| `supplyNeedyItemPercent` | 50 | 前线部队兵装覆盖率低于该值 → 视为需要补给（%） |
| ~~`supplyItemCarryPercent`~~ | — | 已移除：抽取比例改为按 1:1 配比动态折算 |
| `supplyMinCarryTroops` | 3000 | 兵装不足时，可装备兵力低于该值则取消出征 |
