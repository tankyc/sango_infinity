---

## 0. 阅读说明

### 0.1 事件编号规则

`E<时期号><序号>`，例如 `E103` = 第 1 时期第 3 个事件。

### 0.2 "缺口"列说明

缺口编号 `D1`~`D32` 对应第四章的**设计洞清单**。无缺口标记 = 现有框架（含 `Data/事件系统设计.md` 已补齐项）即可实现。

### 0.3 史料口径

以《三国演义》为主（游戏基调），标注：
- **【史】** = 正史记载、演义未重点描写
- **【演】** = 演义虚构或大幅艺术加工
- **【正】** = 正史与演义基本一致

## D1 武将编入部队 / 创建部队时指定成员

**问题**：`TroopCreateEffect` 需要能精确指定"主将 + 副将 1 + 副将 2"，并能设置兵力、兵种、士气、位置。266 个事件里过半涉及具体武将。

**现状**：`Troop` 有 `Leader / Member1 / Member2`；`DuelManager.BuildParam` 就是从这三者取人。

**补齐**：

```jsonc
{ "Type": "TroopCreate", "Params": {
    "ForceSlot": "ActionForce",
    "LeaderSlot": "ActionPerson",
    "MemberSlots": ["Slot3", "Slot4"],
    "TroopType": "Cavalry",
    "TroopCount": { "GainPlace": "EventTroopCountNormal" },
    "SpawnAt": { "Mode": "CitySurround", "CitySlot": "ActionCity", "Radius": 2 },
    "Morale": 90,
    "Name": "{:ActionPerson}军"
} }
```

需要 `SpawnAt.Mode`：`City` / `CitySurround` / `FixedCell` / `NearSlot`。
`TroopCount` 走 `GainPlace` 满足"不硬编码数值"的硬约束。

## D2 武将 / 部队位移

**问题**：
- "千里走单骑"：关羽要带嫂嫂从许昌走到河北，途中过五关
- "赵云长坂坡"：刘备军被冲散，赵云在乱军中移动
- "邓艾偷渡阴平"：部队穿越不可通行地形
- "诸葛亮出山"：诸葛亮从隆中移到新野

**现状**：`Person.ChangeCurrentCity(City)` 只能整城移动；`Troop.cell` 是格子。

**补齐**：

```jsonc
{ "Type": "PersonMoveToCity", "Params": { "Slot": "TargetPerson", "CitySlot": "ActionCity" } }
{ "Type": "TroopMoveToCity",  "Params": { "Slot": "ActionTroop", "CitySlot": "TargetCity", "AllowThroughEnemy": true } }
{ "Type": "TroopTeleport",    "Params": { "Slot": "ActionTroop", "Cell": { "X": 120, "Y": 88 } } }
```

`AllowThroughEnemy` 对应"过五关斩六将"的**强行穿越**语义：穿越时若遇敌则触发战斗/单挑事件（可配 `OnInterceptEventId`）。

## D3 单挑 / 舌战的强制结果

**问题**：
- "关羽斩颜良"：单挑结果**必须**是颜良死。现有 `Duel.ResultHandler` 是概率判定（逃走/被俘/死亡）
- "诸葛亮骂死王朗"：舌战结果必须是王朗死
- "三英战吕布"：吕布**必须**败走但**不死**（历史性约束）
- "赵云长坂坡"：赵云必须连胜，不能败

**现状**：`Duel.cs` 的 `ResultNormal / ResultInjury` 走概率；`DuelType_Event` 有分支但无人设置。

**补齐**：

```jsonc
{ "Op": "Duel", "Params": {
    "ChallengerSlot": "ActionTroop",
    "ChallengedSlot": "TargetTroop",
    "ForceAccept": true,
    "AsEvent": true,
    "Outcome": {
      "Winner": "Challenger",
      "ChallengedResult": "Death",     // Death / Capture / Escape / Injury / None
      "ChallengerResult": "None",
      "IgnoreGovernorImmunity": true,  // 绕过 Duel.cs:642 的君主豁免
      "BonusToChallenger": 30          // 临时武力加成（"偷袭"判定）
    },
    "Next": "afterDuel"
} }
```

需要把 `Outcome` 下传给 `Duel` 的结果处理，覆盖概率判定。`IgnoreGovernorImmunity` 是 D4 的单挑版。

## D4 强制死亡 / 强制处决

**问题**：
- "吕布之死"：吕布是君主，`Duel.cs:642` 有君主豁免（不可被俘/战死，改判逃走）→ 白门楼斩吕布**做不到**
- "关羽之死"：关羽被孙权所杀，属于**敌方处决**，不是战场上被打死
- "曹髦之死"：司马昭弑君
- "华佗之死"、"孔融之死"：非战斗死亡

**现状**：`PersonExecute` 效果在框架里已设计，但没考虑：
1. 君主豁免（Duel 内的判定）
2. 势力灭亡时君主的默认处置（逃走/在野）

**补齐**：
- `PersonExecuteEffect.Params.Force = true` 绕过一切豁免
- `PersonDieEffect.Params.Cause = "Execute" / "Illness" / "Suicide" / "Battle" / "Natural"`（对应 D30）
- 新增条件 `PersonIsGovernorOf`（已有）用于"君主才有的特殊处理"

## D5 跨回合事件链 / 延迟执行（**最严重的设计洞**）

**问题**：原设计明确写了"事件立即结算、不做跨回合挂起"。但真实历史事件大量是**分阶段推进**的：

| 战役 | 阶段 | 跨度 |
| --- | --- | --- |
| 官渡之战 | 白马 → 延津 → 相持 → 许攸投曹 → 火烧乌巢 → 大捷 | 数月 |
| 赤壁之战 | 长坂 → 出使江东 → 舌战 → 蒋干盗书 → 连环计 → 借东风 → 火攻 → 华容道 | 数月 |
| 夷陵之战 | 刘备伐吴 → 陆逊坚守 → 火烧连营 | 1 年 |
| 诸葛亮北伐 | 出师表 → 失街亭 → 陈仓 → 五丈原 | 7 年 |
| 三顾茅庐 | 一顾(207冬) → 二顾(207年底) → 三顾(208春) | 数月 |

**原设计的做法（用 `FireCountCompare` 反复触发）只适合"可重复事件"，不适合"需要精确控制下次触发时间"的战役。**

**补齐：新增 `ScheduledEventQueue`（定时事件队列）**

```jsonc
{ "Op": "Schedule", "Params": {
    "TargetEventId": 4102,          // 或 "InlineEffects": [ ... ]
    "DelayTurns": 3,                // 3 回合后
    "CancelIf": { "Type": "ForceAlive", "Params": { "Slot": "ActionForce" } },   // 条件不满足则取消
    "ContextSlots": true            // 继承当前事件的槽位绑定
} }
```

运行时结构：

```csharp
/// <summary>定时事件项：在指定回合执行某事件或某效果组</summary>
[JsonObject(MemberSerialization.OptIn)]
public class ScheduledEventItem
{
    [JsonProperty] public int TargetEventId;      // 要触发的事件（0 表示只执行 InlineEffects）
    [JsonProperty] public int FireTurn;           // 绝对回合数（FireTurn = 当前回合 + DelayTurns）
    [JsonProperty] public int ChainId;            // 所属事件链（用于编辑器分组展示与整体取消）
    [JsonProperty] public Dictionary<string, int> BoundSlotIds;  // 继承的槽位绑定（对象 Id）
    [JsonProperty] public string CancelConditionJson;             // 取消条件
}
```

`ScenarioEventManager.Update()` 每回合检查 `FireTurn <= 当前回合` 的项并执行。

**配套：事件链（EventChain）**

`EventDefinition` 增加：

```jsonc
"Chain": { "ChainId": 4001, "Name": "赤壁之战", "Stage": 4, "StageName": "蒋干盗书" }
```

编辑器可按 `ChainId` 分组，把"赤壁之战"折叠成一个战役，展开看 8 个阶段。同时提供"整链取消 / 整链重播"。

## D9 日期锚点索引与性能

**问题**：266 个事件，若每次 hook 都遍历全部并求值条件树，开销不可接受（`Condition.Check` 有字符串匹配、对象查找）。

**补齐**：

1. **二级索引**：`Dictionary<EventTriggerKind, List<EventDefinition>>` + 每个 Kind 内按 `EarliestYear` 排序，用 `Info.year` 二分裁剪。
2. **`Trigger.EarliestYear / LatestYear`** 作为**索引键**（必填，编辑器自动从条件树里的 `TimeRange` 提取/校验一致性）。
3. **快速淘汰**：条件树求值前先跑一遍"廉价条件"（`FlagCheck` / `EventFired` / 日期），昂贵的（`ForceCityCount` 要遍历）放后面。`EventConditionNode` 增加 `Cost` 分级，求值器按 Cost 升序短路。
4. **候选上限**：单次 hook 内最多求值 `N=16` 个候选（超出记 `Log.Warning`）。
5. **每回合检查预算**：`ScenarioEventManager` 记录本回合已求值事件数，超预算则推迟到下一回合。

## D12 历史性强度

**问题**：玩家若把刘备提前灭了，"三顾茅庐"还有意义吗？三国志系列有"史实/架空"模式。

**补齐**：

```jsonc
"Mode": "Semihistorical",   // Historical / Semihistorical / Flexible
"HistoricalLock": {
  "ProtectSlots": ["ActionPerson", "TargetPerson"],   // 这些角色在事件链完成前不会被消灭
  "RestoreIfNeeded": true                             // 若已灭亡则"复活"（仅 Historical 模式）
}
```

- `Historical`：条件宽松 + 强制保护关键人物 + 必要时拉回历史（适合"演义模式"剧本）
- `Semihistorical`：条件满足即触发，结果可偏移（**默认**）
- `Flexible`：条件严格，局势不符就不触发（适合"自由模式"剧本）

剧本级默认值放 `Scenario.Cur.Variables.HistoricalEventMode`（遵守"配置不硬编码"约束）。

## D21 事件调试与回溯

```jsonc
{ "Type": "ForceRename", "Params": { "Slot": "ActionForce", "Name": "魏", "FlagColor": 5 } }
{ "Type": "ForceDestroy", "Params": { "Slot": "TargetForce", "AbsorbBy": "ActionForce" } }
```

> "势力复活"（Historical 模式下被灭势力重新出现）成本高，建议 `Historical` 模式改为"**关键人物与关键城池保护**"，而不是真复活。

## D29 武将登场与在野出现

**问题**：三国武将按史实年份登场（如姜维 228 年、陆逊 203 年）。未登场状态是 `PersonStateType.Invalid`，在野是 `Unemployed`。

**补齐**：
```jsonc
{ "Type": "PersonAppear", "Params": { "Slot": "TargetPerson", "CitySlot": "ActionCity", "AsWild": true } }
```
需要处理 `Invalid → Unemployed` 的状态迁移 + 加入 `City.wildPersons`。

## D30 死亡方式区分

**问题**：战死、病逝、被处决、自刎、殉国、老死——表现与后果不同（病逝不掉忠诚、处决掉名声、自刎激励士气）。

**补齐**：
```jsonc
{ "Type": "PersonDie", "Params": {
    "Slot": "TargetPerson",
    "Cause": "Illness",           // Battle / Illness / Execute / Suicide / Natural / Assassinate
    "KillerSlot": "ActionPerson", // 可选
    "Notify": true
} }
```
`PersonExecuteEffect` 等价于 `Cause = "Execute"`，保留为便捷别名。

## D31 事件触发时刻精度

**问题**：
- "十常侍之乱"发生在**回合内的某次操作中**
- "高平陵之变"、"钟会之乱"是**政变**，需要在特定条件下瞬间发生
- "涪城会"（二刘反目）需要**宴会中**触发

**补齐**：
- `Trigger.Timing`：`BeforePlayerAction` / `AfterPlayerAction` / `DuringBattle` / `AfterBattle` / `AnyTime`
- 新增 hook 需求：`OnBattleRoundEnd`（战斗中每轮结束）—— 现有 `OnDuelFinished` 不够
- `Op: Interrupt`：强行打断玩家当前正在进行的操作并插入事件

# 第五章 结论

1. **266 个历史事件中，现存框架（`Data/事件系统设计.md` 的 P1 范围）能直接覆盖约 60 个（23%）**，主要是单回合、双势力、无状态依赖的台词类事件。
2. **最致命的三个洞**：
   - **D5 跨回合事件链** —— 所有战役级事件都做不了（官渡、赤壁、夷陵、北伐）
   - **D11 AI 指令驱动** —— 事件只能"演"，不能"让 AI 去做"，历史推演无法发生
   - **D21 调试与回溯** —— 266 个事件没有调试手段等于不可维护
3. **建议的落地节奏**：先做 **P1 的 13 项**，用"官渡之战"作为端到端验收（它同时命中 D5 D6 D7 D8 D11 D21 D26），跑通后再铺历史线。
4. **强烈建议的降本手段**：D22 模板库 + CSV 批导。否则 266 个事件的手工配置量不可接受。
