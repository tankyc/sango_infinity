## 一、架构决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 存储形式 | **全部扁平具名字段** | 可读性最好、无错位风险、JSON 直观、编辑器可直接绑定 |
| 字段命名 | 语义前缀（`troop*` / `duel*` / `domestic*` / `*Scale` / `*Add`） | 与既有 `falseReportSuccessAdd` 风格统一 |
| 默认值 | 倍率类 = **100**，加值类 = **0** | 老数据/未填字段自动中性，行为不变 |
| `kind` | 沿用既有编号（1胆小 2冷静 3刚胆 4莽撞），新性格顺延 | 符合你的要求 |
| 参数归属 | 性格数值 → `Personality`；框架参数（开关/钳制）→ `AIConfig` | 数据与框架分离 |

## 七、兼容性与安全

| 风险 | 措施 |
|---|---|
| **老存档** | 新增字段为 int，反序列化缺失 → 保留 C# 初始值（中性）✓ |
| **数据表未补** | 全默认中性 → 行为等同未引入 ✓ |
| **两系统被激活** | `Tendency` 填值后 `ForceAI`/外交行为变化 → **需实测回归** |
| **单挑改造** | 弃用 `warTendencyAdd` 改用 `duelAcceptAdd` → 行为会变，需回归 |
| **内政接入** | 13 处折算点均需改 → 建议先接 3~5 项验证，再全量 |
| **极端值** | 部队层双层钳制；内政/单挑建议加 `clamp(50, 200)` |
| **性能** | 纯字段访问，无字典/遍历开销 ✓ |
