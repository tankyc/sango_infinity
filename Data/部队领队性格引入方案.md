# 部队领队性格引入方案（详细设计）

> 状态：**待确认**（本文档只做设计，尚未改动代码）
> 决策前提：作用点 **1+2+3 全做** / 角色**按性格强度加权** / 倍率**钳制可配（默认 50%~200%）**

---

## 一、数据基础（零成本）

| 环节 | 现有设施 | 说明 |
|---|---|---|
| 部队领队 | `Troop.Leader` → `Person` | 已存在 |
| 领队性格 | `Person.mPersonality` → `Personality` | 已存在 |
| 倾向字段 | `warTendencyAdd` / `defenseTendencyAdd` / `diplomacyTendencyAdd` / `economicTendencyAdd` | 已存在，**部队层面完全未使用** |
| 计略倾向 | `falseReportCriticalAdd`（伪报）、`disturbCriticalAdd`（扰乱） | 已存在，仅用于命中/暴击结算，**AI 选技能时未使用** |
| 既有先例 | `ForceAI.GetAIPersonality(Person)` | 用同一套数据推导**势力**个性 |

**结论：数据层零成本，只需在已建好的 `AIPolicy` 管线上再叠一层。**

## 二、⚠️ 数据源修正（重要）

### 2.1 原方案的阻塞问题

原设计依赖 `Personality` 的四个倾向字段：

```csharp
public int warTendencyAdd;        // Personality.cs 有定义
public int defenseTendencyAdd;
public int diplomacyTendencyAdd;
public int economicTendencyAdd;
```

但全项目检索确认：**这些字段在数据表中完全不存在**。
`Build/Content/Data/Common/Personalities.json` 是唯一数据源，其中每个性格仅有：

```
kind, falseReportSuccessAdd, disturbSuccessAdd, calmdownSuccessAdd,
ambushSuccessAdd, infightingSuccessAdd, sorcerySuccessAdd,
falseReportCriticalAdd, disturbCriticalAdd
```

**后果**：倾向字段反序列化后恒为 `0` →

| 影响 | 结果 |
|---|---|
| 作用点 1 倍率修正 | 恒为 100%，**完全无效** |
| 作用点 2 好战指数 | 恒为 0，**角色覆盖永不触发** |
| 附带发现 | `ForceAI.GetAIPersonality` 因此**恒返回 `Balanced`**（既有隐性缺陷） |

### 2.2 修正方案：改用 `kind` 作为性格档位

`Personality.kind` 有完整真实数据（1~4），语义明确，直接作为性格档位使用。

| Id | 名称 | `kind` |
|---|---|---|
| 1 | 胆小 | 1 |
| 2 | 冷静 | 2 |
| 3 | 刚胆 | 3 |
| 4 | 莽撞 | 4 |

## 三、作用点 1：倍率修正

### 3.1 性格档位权重表（替代原"倾向值 × 系数"）

```csharp
/// <summary>
/// 单个领队性格档位的部队权重（倍率均为百分数，100 = 不修正）。
/// 按 Personality.kind 索引：1=胆小 2=冷静 3=刚胆 4=莽撞
/// </summary>
public class TroopPersonalityWeights
{
    /// <summary>攻击收益倍率（%）</summary>
    public int attackScale = 100;
    /// <summary>反击惩罚倍率（%）</summary>
    public int counterPenaltyScale = 100;
    /// <summary>撤退概率修正（%），直接加到态势档位的撤退概率上</summary>
    public int retreatBonus;
    /// <summary>好战度（-100~100）：正值倾向攻坚，负值倾向防守</summary>
    public int aggression;
}
```

**默认值**

| 性格 | attackScale | counterPenaltyScale | retreatBonus | aggression |
|---|---|---|---|---|
| 1 胆小 | 80 | 150 | **+20** | **−40** |
| 2 冷静 | 100 | 100 | 0 | 0 |
| 3 刚胆 | 110 | 90 | −5 | **+30** |
| 4 莽撞 | 130 | 60 | **−20** | **+60** |
| 未知 / null | 100 | 100 | 0 | 0 |

### 3.2 钳制（保守值，按你的要求）

```
leaderAttackScale  = clamp(attackScale,         leaderScaleMin, leaderScaleMax)   // 默认 50 ~ 150
leaderCounterScale = clamp(counterPenaltyScale, leaderScaleMin, leaderScaleMax)
```

> `leaderScaleMax` 已按"保守值"从 200 **下调为 150**。

### 3.3 合成（叠加在现有管线之上）

```
finalAttackScale  = tier.attackScale  × role.attackScale  / 100 × leaderAttackScale  / 100
finalCounterScale = tier.counterPenaltyScale × role.counterPenaltyScale / 100 × leaderCounterScale / 100
```

**极值示例**（保守参数）

| 情形 | tier | role | leader | 连乘 | 最终（经合成钳制） |
|---|---|---|---|---|---|
| 碾压 + 攻坚 + 莽撞 | 140 | 120 | 130 | 218% | **≤180%** |
| 碾压 + 攻坚 + 刚胆 | 140 | 120 | 110 | 185% | 185% |
| 均势 + 无角色 + 冷静 | 100 | 100 | 100 | 100% | 100% |
| 危局 + 守备 + 胆小 | 50 | 80 | 80 | 32% | ≥40% |

### 3.4 ⚠️ 建议新增：最终合成倍率钳制（请审核）

三层连乘的极值（218%）说明单靠个人层钳制不足。建议增加一组**最终钳制**：

```csharp
/// <summary>合成后攻击倍率的最终上下限（%），防止三层连乘失控</summary>
public int finalAttackScaleMin = 40;
public int finalAttackScaleMax = 180;
/// <summary>合成后反击倍率的最终上下限（%）</summary>
public int finalCounterScaleMin = 40;
public int finalCounterScaleMax = 180;
```

## 四、作用点 2：角色覆盖（按性格强度加权）

### 4.1 性格强度指标

```
好战指数 strength = |aggression|        // 取自性格档位权重表
```

| 性格 | aggression | strength |
|---|---|---|
| 胆小 | −40 | **40** |
| 冷静 | 0 | **0** |
| 刚胆 | +30 | **30** |
| 莽撞 | +60 | **60** |

### 4.2 性格推导的角色

```
aggression > 0  →  Assault  攻坚
aggression < 0  →  Defender 防守
aggression == 0 →  不产生性格角色（完全以任务为准）
```

### 4.3 决策流程（加权：强度越大越容易覆盖）

```
① 若任务无法映射出明确角色（追击 / 无任务）
       → role = 性格角色

② 若任务可映射，且 strength >= leaderRoleOverrideThreshold(默认 20)
       → role = 性格角色            ← 性格强烈，覆盖任务

③ 若任务可映射，且 strength <  20
       → role = 任务角色            ← 性格温和，以任务为准
```

**加权体现**：强度未达阈值时性格**不抢占**角色，但仍通过作用点 1 的倍率持续施加影响 ——
即"强度越大影响越大"，而非简单二选一。

> 阈值 20 的取值依据：冷静(0) 永不覆盖；刚胆(30)、胆小(40)、莽撞(60) 均可覆盖。

### 4.4 决策表

| 任务 | 领队性格 | strength | 最终角色 |
|---|---|---|---|
| 攻城（→攻坚） | 冷静 | 0 | 攻坚（任务优先） |
| 攻城（→攻坚） | 莽撞 | 60 | 攻坚（方向一致） |
| 守城（→防守） | 莽撞 | 60 | **攻坚**（性格覆盖任务） |
| 守城（→防守） | 冷静 | 0 | 防守（任务优先） |
| 追击（无映射） | 胆小 | 40 | 防守（性格兜底） |
| 追击（无映射） | 冷静 | 0 | 攻坚（ResolveRole 默认） |

## 五、作用点 3：计略技能偏好（详细计算公式 · 供审核）

### 5.1 背景：现有暴击公式

来自 `SkillCriticalMethod.cs`：

```
伪报暴击率 = (A智 + C_伪报 − B智/2) × 10 / 100
扰乱暴击率 = (A智 + C_扰乱 − B智/2) × 10 / 100

A智 = 施法方主将智力，B智 = 目标智力
C 由**施法方（用计方）主将性格**决定，取值即 Personality 的 *CriticalAdd 字段
```

### 5.2 数据来源与实际取值

`Personalities.json`（全部 4 种性格，均为真实数据）：

| Id | 名称 | `kind` | `falseReportCriticalAdd` | `disturbCriticalAdd` |
|---|---|---|---|---|
| 1 | 胆小 | 1 | **+10** | **−5** |
| 2 | 冷静 | 2 | **+5** | **0** |
| 3 | 刚胆 | 3 | **0** | **+5** |
| 4 | 莽撞 | 4 | **−5** | **+10** |

取值范围：**−5 ~ +10**，4 个离散值。

### 5.3 完整计算公式

```
【输入】领队性格对当前技能的"施法者倾向值 C"

    skill.Id == 24（伪报） → C = Leader.mPersonality.falseReportCriticalAdd
    skill.Id == 25（扰乱） → C = Leader.mPersonality.disturbCriticalAdd
    其它技能               → 不修正（scale = 100，直接返回原分）

【step 1】原始倍率
    rawScale = 100 + C × leaderSkillTendencyScalePerPoint

【step 2】钳制
    scale = clamp(rawScale, leaderSkillScaleMin, leaderSkillScaleMax)

【step 3】应用（三个条件同时满足才生效）
    条件① skill.IsStrategy()         仅计略技能（kind == 3）
    条件② score > 0                  误伤友军的负分不被放大
    条件③ useLeaderSkillPreference   总开关
    score' = score × scale / 100
```

### 5.4 默认参数（保守）

| 参数 | 默认值 | 说明 |
|---|---|---|
| `leaderSkillTendencyScalePerPoint` | **5** | 每点 C 折算的收益倍率（%） |
| `leaderSkillScaleMin` | **75** | 倍率下限（允许负向惩罚） |
| `leaderSkillScaleMax` | **150** | 倍率上限 |

### 5.5 效果表（默认参数）

| 领队性格 | C_伪报 | 伪报 scale | C_扰乱 | 扰乱 scale |
|---|---|---|---|---|
| 胆小 | +10 | **150%** | −5 | **75%** |
| 冷静 | +5 | 125% | 0 | 100% |
| 刚胆 | 0 | 100% | +5 | 125% |
| 莽撞 | −5 | 75% | +10 | **150%** |

**方向一致性**：莽撞之将更爱放扰乱、更不爱放伪报；胆小之将相反 ——
与两组暴击系数（`胆小→伪报+10` / `莽撞→扰乱+10`）的原始设计**完全同向**，
不会出现"AI 偏爱自己放不准的计略"的逻辑矛盾。

### 5.6 在评分链中的位置

```
SkillStatusPriority（基础收益，含计略成功率门槛判定）
      ↓   ← 作用点 3 在此处应用（仅计略、仅正分）
ApplyTaskBonus（任务倍率）
      ↓
PriorityAction（× tier × role × leader 倍率）
      ↓
RandomGetTop(bestN)
```

### 5.7 审核要点

| 待确认 | 说明 |
|---|---|
| 设计思路 | 用"暴击加成本身"作为偏好强度（擅长暴击 → 更愿释放），是否认可 |
| 钳制区间 | 75%~150%（可加可减）或改为 100%~150%（只加不减） |
| 作用范围 | 仅 `IsStrategy()` 计略；是否也需覆盖普通战法 |
| 数据局限 | 镇静/伏兵/妖术/内讧 无施法者倾向字段，不参与偏好修正（不改数据表） |

public int finalAttackScaleMin = 40;

// ---------- 角色覆盖 ----------

/// <summary>计略偏好倍率下限（%）</summary>
public int leaderSkillScaleMin = 75;
/// <summary>计略偏好倍率上限（%）</summary>
public int leaderSkillScaleMax = 150;

// ---------- 择优池（性格影响） ----------
/// <summary>好战指数每点使择优池变化的幅度：正 aggression 缩小池（更专注最优解），负 aggression 扩大池</summary>
public int leaderBestNPerPoint = 0;      // 见 6.2

// ---------- 安全阀 ----------

### 6.2 择优池受性格影响（按你的要求启用）

`AIPolicy.bestN` 目前直接取 `tier.bestN`。启用后按性格调整：

```
finalBestN = tier.bestN - aggression × leaderBestNPerPoint / 10
finalBestN = clamp(finalBestN, bestNMin, bestNMax)
```

| 参数 | 建议默认 | 说明 |
|---|---|---|
| `leaderBestNPerPoint` | **5** | 好战度每 10 点使择优池变化 5（缩小/扩大） |
| `bestNMin` | 1 | 池下限（1 = 只取最优解） |
| `bestNMax` | 8 | 池上限 |

**效果示例**（`tier.bestN = 5` 均势档）：

| 性格 | aggression | finalBestN | 行为含义 |
|---|---|---|---|
| 莽撞 | +60 | 5 − 30 → **1** | 果断取最优解，不犹豫 |
| 刚胆 | +30 | 5 − 15 → **1** | 偏果断 |
| 冷静 | 0 | **5** | 保持均势档的多样选择 |
| 胆小 | −40 | 5 + 20 → **8** | 选择面更宽，行为更多变（"拿不定主意"） |

> 语义自洽：好战者专注单一最优行动，胆怯者在多个选项间摇摆。

## 八、边界与安全阀

| 风险 | 描述 | 措施 |
|---|---|---|
| **莽将送死** | 莽撞 + 危局档仍强攻 | `leaderIgnoreRetreatInCritical = true` |
| **极端性格拉爆** | 单层倍率过大 | `leaderScaleMin/Max`（50~150） |
| **三层连乘失衡** | 140% × 120% × 130% = 218% | **新增** `finalAttackScaleMin/Max`（40~180） |
| **性格数据缺失** | `mPersonality == null` 或 `kind` 越界 | 走 `personalityUnknown`（全 100%），行为等价于未引入 |
| **削弱任务导向** | 性格覆盖后偏离战略 | `useLeaderRoleOverride = false` 一键关闭覆盖 |
| **计略过度倾向** | 莽撞之将只放扰乱 | `leaderSkillScaleMax = 150` 上限 |
| **性能** | 性格为对象字段访问，无遍历 | 无额外开销 |
