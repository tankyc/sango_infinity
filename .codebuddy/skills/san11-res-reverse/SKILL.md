# 三国志11 资源逆向（San11Res）

## 0. 正本与边界

- 工具与解析器的**唯一正本**：`d:\sango_infinity_tools\San11Res\`（`export.py` + `san11res/` 包 + README）。
- 结论文档：同目录 `README.md`，§0.1 是「数据溯源清单」、§0.2 是「仍是推断的项」、§4.x 是各格式规格。
- 游戏与资源：`D:\game\San11pk\san11pk.exe`、`D:\game\San11pk\Media\san11pkres.bin`。
- 不要在别处复制一份解析器。曾因「改副本不生效」白查半天。

## 1. 三条纪律（违反必翻车）

1. **能落到原始记录的才算事实。** 每条结论都要能写成「归档号 / 文件偏移 / exe 地址」+ 观测值。
   落不到的，在代码注释和文档里显式标「推断」，不要混进事实段（§0.2 那一节就是为此存在）。
2. **两个独立证据才算通。** 典型 pairing：结构自洽（块数 == 累计表项数 == 头字段）+ 语义自洽
   （帧号最大值 == 帧数−1）。只有一个证据时写「疑似」。
3. **反例优先。** 改完解析器先找**最不可能通过**的样本跑（最大/最小/最怪的那个），
   全量 600 个都过不代表对，只是没遇到反例。

## 3. 十个硬事实（先记住，能省几小时）

1. **归档没有文件名。** `LINK` 头 + `u32 条目数` + 从 `0x10` 起 `(offset,size)×N`，
   条目正文以自己的 4 字节 magic 开头，只能按编号访问。magic → 格式的对照见 `references/formats.md`。
2. **exe 里没有「模型 ↔ 贴图」id 表。** 4 字节对齐/非对齐两种方向全扫过，0 命中；
   游戏是按路径名加载的。所以配对只能靠 `index_map.json` 里的文件名规则。
3. **模型文件只有网格 + 绑定姿势**，动作在独立的 `.fcv` 里；文件自带的骨骼块（`0x30/0x34`）
   是给动作用的，导入摆放要靠 exe 内置的 57 骨骼表（`san11res/wkm_bone_table.json`）。
4. **600 个 `.fcv` 全是事件演出**（`mot_deb` 舌战 322 / `mot_due` 单挑 270 / `mot_dip` 外交 8），
   **没有一个是战场部队的动画**。部队模型在归档里没有任何对应动作。
5. **`.data` 是 154 MB 的运行时静态池**（`0x0089D000`–`0x09C617E0`），文件里绝大部分是 0。
   游戏进程里 `0x009xxxxx` / `0x09xxxxxx` 的地址**也在映像内**，不是 malloc —— 判断「堆还是静态」必须用段表，不能看地址高低。
6. **WKMD 的索引是三角形条带（TRIANGLESTRIP），不是列表**，且必须按「绘制组表」切分，
   组间不能桥接；`0xFFFF` 是条带分隔符，重复索引是退化三角形。
7. **`anim_sprites.wft`（id 2195）不是「N 页 256×512」**，是多个不同尺寸子图首尾相接，
   子图起点既不在页边界也不在 2 的幂格子上。按页切永远差几个像素。
8. **AIMG 组表里的 `(0,0)` 是「空槽」不是「表尾」**，遇到必须跳过继续读，否则丢掉一半动作。
9. **音效不在 ogg 里**：界面/打击/单挑音效在 13 对 `.whd/.wbd` 里；KOVS 是 ogg 但按
   `byte ^ (i & 0xFF)` 混淆过，直接搜 `OggS` 搜不到。
10. **`FCVD` 的 `0x0C` 是总帧数、`0x0E` 是块数**（不是「起止帧」）。
    判据：块数 == 累计表项数；帧号最大值 == 帧数−1。块 = 一根骨骼的一个属性通道。

## 4. 校验判据（回答「你凭什么说解对了」）

| 对象 | 判据 | 工具 |
|---|---|---|
| WKMD 绕序/拆面 | **面法线 · 顶点法线** 一致率 > 0.8（多数 0.96）；错解在 0.4 徘徊 | 导出时打印 |
| WKMD 摆放 | 套骨骼表后顶点包围盒 ≈ 文件声明包围盒（如 999 段0 顶部 185.0 vs 声明 184.98） | `_wkm_verify.py` |
| 蒙皮权重 | stride44 三分量和 ≈ 1 的占比 78.1%，其余 < 1；stride36 只有 0/0.7/0.8/0.9/1.0 档 | `_probe_weight_sem.py` |
| FCVD 旋转 | 同骨 x²+y²+z²+w² = 1（误差 < 1e-3）；静止骨 0/0/0/1 | `fcvd.parse` |
| FCVD 结构 | `0x0E` 块数 == 累计表项数 == 实际解析块数；帧号 ∈ [0, frameCount) | `_q_fcv_headers.py` |
| AIMG 与图集配对 | 内区覆盖率 − 外环覆盖率 **≥ 0.20**（真解 0.30~0.32，噪声 ~0.10） | `verify_aim_atlas.py` |
| whd/wbd 切分 | 样本「偏移+长度」覆盖 `.wbd` **100%** | `audio.parse_whd` |
| 归档命名 | 每块「块内 magic 条数 == exe 该目录唯一路径数」，全过才写 `index_map.json` | `map_from_exe.py` |

**只靠外观判断一律不算验证**：图集里随便压一块也能切出半张人形（2199 就骗过一次），
模型「看着像」也一样 —— 上表每条都是可量化的，用它们。

## 5. 卡住时的定位套路

**现象：某个量在归档里找不到对应值（如「运行时看到 21 帧，600 个 fcv 里没有 21 帧的」）。**
→ 先怀疑自己读错了字段。把头部按 `u8/u16/u32` 三种宽度都 dump 一遍，再拿一个已知样本反向核对
（例：`1121` 头 `+0x0C=112`，而它最关键帧帧号 111 → 立刻确认 `0x0C` 是帧数）。

**现象：静态在 exe 里搜不到某个地址/常量。**
→ 若目标在 `.data` 的零填充区，它就是运行时才写的，静态必然搜不到。改走运行时：
`_dbg_probe.py --peek 0x...` 直接 dump，或 `--guard` 给目标页加 `PAGE_GUARD` 抓访问点。

**现象：断点命中但栈/参数完全不合理。**
→ 断点下在了循环体或函数中部。先用 `_disasm.py --from` 把前后 0x200 字节反汇编出来确认指令边界
（capstone 从任意偏移解码会静默错位，必须从 `int3` 填充之后重新起步），再找真正的函数入口。

**现象：某个资源到底被谁引用。**
→ 三级武器：① `_exe_xref.py` 找字符串交叉引用；② `_exe_ptrfind.py` 找 `.data/.rdata` 里指向它的指针；
③ `_dbg_probe.py --guard` 抓运行时的读写点。

**现象：判断某个游戏行为是资源驱动还是程序化。**
→ 直接看归档里有没有对应资源。没有就是程序化（例：战场部队没有任何 fcv，所以是整模型变换）。
不要因为「看起来有动画」就假定存在骨骼动画数据。

## 6. 踩坑速查（完整版见 `references/pitfalls.md`）

按代价从高到低：

1. **模型索引块不能从 `0x60` 读**（`0x60` 是顶点块结束，中间夹着每顶点 4 字节全 `0xFF` 的附加表），必须用段描述块 `+0x28`。
2. **索引按 3 个一组读会丢 2/3 的面**：它是条带，要滑窗展开 + 跳过退化 + `0xFFFF` 断链。
3. **段数要读 `0x44`**，只读前两段会缺一整块几何（1045 赵云有 3 段）。
4. **OBJ 的 `f` 索引是全局连续的**，多段导出必须累加前面段的顶点/UV/法线数，否则第二段起全部悬空。
5. **条带展开后一半面绕序是反的**（文件里本来就混着两种方向），要用顶点法线校正，否则背面剔除=缺面、透过去=串联。
6. **整段当一个大条带展开会在组间产生垃圾面**，必须按绘制组表逐组切。
7. **aim 的 `+0` 是累计时间戳不是帧时长**，必须差分；直接当 duration 用会「一帧比一帧慢」。
8. **2195 图集的子图起点不在页边界**，按「页 × 524288」推算全错（2203 的块比边界晚 4 像素）。
9. **`(0,0)` 槽不是表尾**，遇空槽 `break` 会丢一半动作（2200 从 42 组掉到 18 组）。
10. **`0x0C/0x0E` 不是起止帧**（本次修正）；**`块数 ÷ 7` 不是骨骼数**通用公式（164 块 = 38 骨骼，不是 23）。
11. **WOW64 下硬件写断点（Dr 寄存器）经 `Wow64SetThreadContext` 不生效**，用 `PAGE_GUARD` 替代。
12. **断点别下在 `0x44ABA0`** —— 那是骨骼矩阵搬运循环的循环体（`mov eax,[esi+0x58]` / `shl edx,6` / `add edi,0x28`），会被误当成「动作装载」。
13. **别信「切出来像小兵」**：密集图集里任何位置都能切出人形，要看得分 + 兵种外观两个判据。
14. **Unity 端 Play 会重载域**，静态计数和 `EditorApplication.update` 回调全丢，待办状态要放 `SessionState` 并在 `[InitializeOnLoadMethod]` 里重挂。

## 7. 交付格式

给结论时固定带三样，缺一样就是没交付：

```
归档号 / exe 地址 + 字节偏移 + 实测值
```

例：

```
1121  mot_due_a_000_m.fcv   +0x08=505 键  +0x0C=112 帧  +0x0E=164 块  8080 字节
1716  mot_due_b_010.fcv     +0x0C=31    +0x0E=147 块  21 骨骼（0..20）
运行时 0x009CF5F0 槽1       {ptr=0x028267A0, 3, bone=21, frame=31} → 指向 1716
```

改了解析器要同时说明：**改了哪个判断、哪条判据仍成立、哪个样本跑过**。
只写「已修复」不算完成。
