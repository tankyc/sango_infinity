全部数值来自对 `san11pkres.bin` / `san11pk.exe` 的直接读取。
权威实现：`d:\sango_infinity_tools\San11Res\san11res\*.py`；叙述版：同目录 `README.md` §4。

## 1. 归档 `san11pkres.bin`

```
0x00  char[4] "LINK"
0x04  u32     条目数（本版 4876）
0x08  u32     版本 1
0x10  (u32 offset, u32 size) × 条目数      # 索引表结束于 39024
```

条目没有文件名，正文以自己的 4 字节 magic 开头。

| magic | 格式 | 数量 | 解析器 |
|---|---|---|---|
| `WFTX` | 贴图 | 1049 | `texture.py` |
| `WKMD` | 模型 | 653 | `wkm.py` |
| `FCVD` | 骨骼动作 / 相机轨迹 | 717（600 + 117） | `fcvd.py` |
| `AIMG` | 序列帧表 | 10 | `aimg.py` |
| `KOVS` | Ogg 音频（异或混淆） | 2027 | `audio.py` |
| `TOD2` | 表情动画 | 38 | 未细解 |
| `NUNO` | 布 / 旗帜 | — | 未细解 |
| `PAC0` | 舌战脸部件 | — | 未细解 |
| `KSEF` | 特效定义 | — | 未细解 |
| `SHEX` `K3ST` `OBJS` `GCOL` `SENV` | 地图 | — | — |

`4713~4786` 这 74 条是 25 字节的位标志表，**不是资源**，扫描时忽略。

## 2. `WFTX`（贴图）

```
0x00 "WFTX"   0x04 "0010"
0x08 u32 文件大小
0x0C u32 标记（不参与解码）
0x10 u16 宽    0x12 u16 高
0x14 u32 标记（24/32/其它，不参与解码）
0x18 像素数据
```

- 每像素字节数 = `(size - 24) / (w * h)`，通道顺序 **BGR**（4 字节时 BGRA）。
- 多页贴图按整页连续排列，页数 = `数据长度 / (w*h*bpp)`；游戏按**纵向堆叠**的大图索引 UV。
- 特例 `id=2195`（`anim_sprites.wft`）**不能按多页理解**：头里的 256×512 只描述最小子图，
  实际是多种尺寸子图首尾相接。详见 §5。

## 3. `WKMD`（模型）

```
0x18 f32[6]  包围盒 min(xyz) / max(xyz)（整模型、多段合并后的范围）
0x30 u32     骨骼数
0x34 u32     骨骼块偏移（每根 64 字节 = 4x4 绑定矩阵）
0x44 u32     段数（部队/道具 = 1；事件人物 = 2~3）
0x50 起      段描述块，每段 0x50 字节
```

段描述块：

```
+0x00 u32 段标识（274 / 278 / 282…，每段 +4）
+0x04 u32 顶点 stride
+0x08 u32 顶点数
+0x0C u32 顶点块偏移
+0x10 u32 顶点块结束
+0x20 u32 固定 101
+0x24 u32 索引数（u16 个数，条带）
+0x28 u32 索引块偏移        ← 索引必须从这里取，不能从 0x60
```

顶点记录（**法线偏移 = stride − 20，UV 偏移 = stride − 8**）：

```
stride 32 → 位置 0 / 法线 12 / UV 24
stride 36 → 位置 0 / 附加 4 / 法线 16 / UV 28
stride 44 → 位置 0 / 附加 12 / 法线 24 / UV 36
```

绘制组表：指针数组在 `0x50 + 段数 × 0x50`，每组描述块 44 字节：

```
+0x00 u16 骨骼序号
+0x02 u16 顶点格式标志（bit2 → 单位阵；bit1 → 单位阵；否则 v' = v · W[骨骼序号]）
+0x10 u32 所属段号          ← 段归属看这个，不要按「顶点连续链」猜
+0x18 u32 图元类型（实测恒 5 = TRIANGLESTRIP）
+0x1C u32 顶点起始（段内）
+0x20 u32 顶点数
+0x24 u32 索引起始（段内）
+0x28 u32 索引数
```

骨骼表合成（`mq_import_wkm.dll` 反汇编得出，三套表见 `wkm_bone_table.json`）：

```
W[0] = M[0];   W[i] = M[i] · W[parent[i]]     （行向量右乘）
```

索引解码：u16 条带滑窗展开 → 跳过重复索引（退化三角形）→ `0xFFFF` 断链 →
奇偶翻绕序 → 逐面用「面法线 · 顶点法线」校正方向。

## 4. `FCVD`（动作）

### 4.1 骨骼动作 `media/event/motion/mot_*.fcv`

```
0x00 "FCVD"   0x04 "0022"
0x08 u32  关键帧总量（= 块数 + 各块记录数）
0x0C u16  动作总帧数（帧号 0 .. 帧数-1）
0x0E u16  块数（= 0x10 起累计表项数 = 有动画的属性通道数）
0x10 u32[] 累计表（递增；靠「不再递增」判表尾）
块头 16B: +0x00 u32 记录数+1   +0x04 u8 类型(恒 3)  +0x05 u8 通道号
          +0x06 u16 骨骼索引   +0x08 u32 记录数     +0x0C u32 0
记录 16B: +0x00 u16 标志(恒 4) +0x02 u16 帧号
          +0x04 f32 值         +0x08 f32 切线1      +0x0C f32 切线2
```

通道号：`6/7/8` = 位移 x/y/z，`34/35/36/37` = 四元数 x/y/z/w。

- 一块 = 一根骨骼的一个属性通道，最多 7 块/骨骼；没动的分量不写块。
- 常见配置：**164 块 / 38 骨骼**（骨号 0..37）；`mot_due_b_010` 是 **147 块 / 21 骨骼**（0..20，恰好 21×7）。
- **`块数 ÷ 7` 不是骨骼数**，别拿它反推。
- 帧号是**逐分量独立打点**，不要强行合并成统一帧序列。
- 加载进内存后，`0x10` 起的偏移表会被**重定位成绝对指针**（偏移表 → 指针数组），静态比对会看起来完全不同。

### 4.2 相机轨迹 `media/event/camera/cam_*.fcv`

```
0x10 起为段偏移表；其后每段是 (u16 标志=4, u16 帧号, f32 x, f32 y, f32 z) 16 字节记录
```

段头布局未完全确认，只做「尽力解析」。

### 4.3 `mot_*.fcv` 命名规则

600 条全是 `media/event/motion/mot_<事件>_<其余>.fcv`，只有三族：

| 事件 | 条数 | 含义 |
|---|---|---|
| `deb` | 322 | 舌战 |
| `due` | 270 | 单挑 |
| `dip` | 8 | 外交 / 会面 |

```
单挑  mot_due_<角色槽 a|b>_<段号 000/010/020…>[_<部位 m|f|c>][_<l|r>].fcv
舌战  mot_deb_<段号>[_<部位 m|f|c|s>][_<层 hi|lo|rg>].fcv
外交  mot_dip_<000|001>_<m|f|c|s>.fcv
```

- `m/f/c/s` 是**角色槽或体型变体**（四者块数同为 164 / 38 骨骼，是同一套骨骼），命名里**没有武将名** → 通用动作集，靠骨骼表适配体型。
- `_l/_r` 成对出现（左右手/脚）；`_hi/_lo/_rg` 是**叠加层**（块数明显变少：`deb_hi` 34/35 块、`deb_lo` 29 块）。
- `rock_l` / `rock_r` 10 条是受击晃动。

### 4.4 运行时「fcv 加载表」（16 字节一条）

进游戏后（**标题画面就够**，不用进单挑）`.data` 静态池里就有一张「已加载 fcv」表，16 字节一条：

```
+0x00 u32  fcv 数据指针（加载后的副本；0x10 起的偏移表已重定位成绝对指针）
+0x04 u32  次指针（同一份 fcv 的另一个视图）
+0x08 u32  类型，实测恒 3
+0x0C u16  骨骼数（= max(骨骼号)+1）
+0x0E u16  帧数（= fcv 头 +0x0C）
```

实测（`_peek_slots.py --scan 0x900000 0x9D0000`）：**268 条**占
`0x009CD150`–`0x009CF630`（591 个位置，占位率 45.3%），分 4 个不连续段（131 / 51 / 80 / 6 条），
段间被别的数据占着；同一 fcv 可出现多条（不同副本），如 `0x009CD270` 与 `0x009CD280` 都是 `mot_deb_120_c`。

`mot_due_b` 六条**全部在表里**，连续排在最末一段、顺序 000→050：

```
0x009CF5E0 → 1715 mot_due_b_000  161 帧 147 块  12256 字节
0x009CF5F0 → 1716 mot_due_b_010   31 帧 147 块  10464 字节
0x009CF600 → 1717 mot_due_b_020   73 帧 147 块  11872 字节
0x009CF610 → 1718 mot_due_b_030  121 帧 147 块   7904 字节
0x009CF620 → 1719 mot_due_b_040   53 帧 147 块  14288 字节
0x009CF630 → 1720 mot_due_b_050  101 帧 147 块  20544 字节
```

装表顺序 = **文件名正序**。`.rdata` 的字符串表是逆序（050→000，定长 40 字节一条，起点 VA `0x75C528`，
600 条），那只是存储布局反着排，**不构成额外的顺序表**。

工具：`python _peek_slots.py --scan 0x900000 0x9D0000`（只读扫描 + 自动匹配归档号）、
`--wait N` 轮询等表出现、`python _q_due_b_slots.py` 动作特征对照。

## 5. `AIMG`（序列帧表）与 `anim_sprites.wft`

### 5.1 AIMG

```
0x00 "AIMG"   0x04 "0001"
0x08 u32 未知（= 11）
0x0C u32 未知（= 6）
0x10 (u32 dataOffset, u32 frameCount) × 槽数
槽数 = (首个 dataOffset − 0x10) / 8；实测 66 槽
帧记录 28B: +0 f32 累计时间戳（不是时长！）
            +4 u32 u0  +8 v0  +12 u1  +16 v1  +20 u32 anchorX  +24 u32 anchorY
```

- `(0,0)` 是**空槽**，跳过继续读，不是表尾。
- 每帧时长 = `t[i] − t[i−1]`（首帧 = `t[0]`）。
- `index` = 槽位下标，**保留空洞不要重编号**，否则与游戏内动作 ID 对不上。
- 实测条数：

```
2196~2199  66 槽全满     174 / 174 / 174 / 162 帧   （2197 与 2198 字节级相同）
2200~2202  66 槽(空 24)  42 组 228 / 204 / 184 帧
2203~2204  66 槽(空 18)  48 组 216 / 193 帧
2205       66 槽(空 60)  6 组 42 帧（1720 字节，只有槽 18~23 有数据）
```

### 5.2 `anim_sprites.wft`（id 2195）

```
0x10 u16 宽=256   0x12 u16 高=512      # 只描述最小子图，不是整图尺寸
0x18 像素 BGRA，共 4194304 字节
```

- 是**多个不同尺寸子图首尾相接**，子图起点不在页边界、也不在 2 的幂格子（2203 的块晚 4 像素，2201 落在 512 行距的第 341 行）。
- `.aim` 里的 `u/v` 是**子图内坐标**；导出时按 `(atlasOffset, atlasWidth, atlasHeight)` 从像素流重排，不要按「第几页 × 524288」推算。
- 已知配对（`names.AIM_ATLAS`）：

```
2200 黄色剑兵    偏移 0        256x512  得分 0.300 ✔
2203 绿色弩兵    偏移 2097168  256x512  得分 0.317 ✔
2201 红色枪兵    偏移 698376   512x256  得分 0.216 ✔
2196 黑紫骑兵    偏移 3074088  512x256  得分 0.218 ✔
2202 蓝色戟兵    偏移 1398796  512x256  得分 0.157 ✘
2199 蓝色戟兵    偏移 1310720  512x256  得分 0.179 ✘
2204 黑紫骑兵    偏移 3145728  512x512  得分 0.205 ✘
2197/2198 黄色剑兵  未对上     256x512  得分 0.089 ✘（帧宽中位 24、高 42，图集里没这个尺寸）
```

## 6. `KOVS`（音频）

```
0x00 "KOVS"   0x04 u32 总大小   0x08 24 字节 0
0x20 Ogg Vorbis 流，按 byte ^ (i & 0xFF) 混淆
```

还原：跳过 32 字节头，第 i 字节异或 `(i & 0xFF)` → 标准 `OggS`。

## 7. `.whd` / `.wbd`（音效库，13 对 / 238 样本）

```
.whd:
  0x00 u32 magic = (库号<<16) | 0x3200     （3D 库以 0x3201 结尾）
  0x04 u32 对应 .wbd 字节数
  描述项 40 字节/条（+2 处有 0x0132 标记）：
    +4  u16 采样率（44100 / 22050）
    +16 u32 帧数
    +20 u32 在 .wbd 中的字节偏移
    +24 u32 采样字节数
.wbd: 裸 PCM 16bit 小端
```

13 对（数据条目 / 头条目）：

```
2267/2268 BNK_INI_3D   2269/2270 BNK_INI_2D   2271/2272 BNK_EVE_2D
2273/2274 BNK_DEB_2D   2275/2276 BNK_DUE_2D   2277/2278 BNK_WAR_3D
2279/2280 BNK_WAR_2D   2281/2282 BNK_ADV_3D   2283/2284 BNK_ADV_2D
2285/2286 BNK_SYS_2D   4864/4865 BNK_PK_1     4866/4867 BNK_PK_2
4868/4869 BNK_PK_3
```

前 10 个库名有 exe 记录（`.rdata` 文件偏移 `0x3F1540`–`0x3F15AC` 连续排列，
`.data 0x4B1438` 有同 10 条的逆序指针数组）；`BNK_PK_1/2/3` 是自拟标签。
`.whd` magic 低 16 位（0x3200/0x3201）**不是** 2D/3D 标记，含义未定。

## 8. `index_map.json`（归档号 → 原版路径）

```json
{ "1121": "media/event/motion/mot_due_a_000_m.fcv", ... }
```

1951 条。来源：`san11pk.exe` 的 `.data` 内嵌「字符串指针数组」（如 `0x49e098..0x49eed4`），
按数组顺序把 `media/...` 路径铺到归档的对应块上，并逐块校验
**「块内该 magic 的条数 == exe 该目录唯一路径数」**，全部通过才写出。

校验锚点（人工确认过，用来判断映射有没有整体错位）：

```
归档 1765 = 赵云头盔贴图
归档 1862 = CHR_H000_chouun_P_FACE000 贴图
归档 999  = CHR_H000_chouun_P_FACE000 模型
归档 857  = 披风 CLOAK202
归档 2207 = UNI00_sword（持剑小人）
归档 2194 = 名马大宛
```

exe 里没有路径的资源（武将立绘 0..715、AIMG、KOVS、PK 追加场景贴图）无法用这张表命名。
