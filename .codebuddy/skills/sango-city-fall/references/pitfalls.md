# 城陷踩坑记录

每条：现象 → 根因 → 修法 → 可复用教训。全部来自本项目真实修复。

---

## 1. 太守凭空消失

**现象**：玩家刚打下的城，回合结束后太守被清空，提示"太守失效"。

**根因**：先 `Leader = atk.Leader` 再 `atk.EnterCity(this)`。
此刻 `newLeader.BelongCity` 还不是本城、也不在本城 `allPersons` 里，
年度巡检按"太守必须在籍"判定并清空。

**修法**：先 `EnterCity` 改户口，再校验 `BelongCity == this && allPersons.Contains(newLeader)` 后赋值。

**教训**：`Leader` 是有外部约束的字段（巡检 / AI / UI 都读），赋值前必须满足那些约束的前提。

出处：`City.cs:2323-2329`（白城分支的同源注释）。

## 2. 城还没"抢完"就变了颜色

**现象**：破城瞬间，小地图与战略地图立刻变成攻方颜色，但掠夺结算的数字还没播完。

**根因**：`CityStateSystem.SetCorps` 被提前到掠夺之前。原版顺序是
`:264-277` 掠夺 → `:278-341` 设施 → `:343-346` 改旗 → `:347-358` 入城。
`SetCorps` 内部会触发 `GameEvent.OnCityChangeForce`，表现层当场刷新。

**修法**：严格按原版顺序，改旗放在掠夺与设施之后。

**教训**：数据上互不影响的步骤，也可能通过事件产生表现层顺序依赖。照抄原版顺序最省事。

出处：`City.cs:2712-2725`。

---

## 3. 亡国时清理港关导致空引用

**现象**：势力被灭，`Force.Ruin` 抛空引用。

**根因**：清理同势力港关的循环里没有排除被攻陷的这座城。
`c.LeaveToWild()` 把 `this.BelongCorps` 置空，而 `Ruin` 读 `BelongForce`（= `BelongCorps?.BelongForce`）时崩。

**修法**：循环加 `c != this`；被攻陷的城由后续改旗流程处理。

**教训**：批量清理同势力对象时，永远先排除"当前正在处理的那个"。

出处：`City.cs:2438-2442`。

---

## 4. 遍历设施时漏元素

**现象**：城陷后仍有几座内政设施保持原归属，改旗不干净。

**根因**：`allBuildings.ForEach(b => b.OnFall(atk))`。
`OnFall` 内部经 `City.OnBuildingDestroy` 把建筑从 `allBuildings` 移除，边遍历边删 → 跳过后续元素。

**修法**：先拷一份快照 `buildingSnapshot` 再遍历。

**教训**：任何 `OnFall` / `Destroy` / `Clear` 都可能修改所属集合。遍历前先快照。

出处：`City.cs:2557-2564`。

## 5. 武将撤到敌城

**现象**：城破后，撤退武将的户口落在敌方城池；下一次城陷时"撤退城市"选到敌城。

**根因**：无条件信任 `BelongForce.CapitalCity`。
`CapitalCity` 是君主户口的派生值（`mGovernor?.BelongCity`），君主出征/在途/死亡时户口留在旧城，
旧城一易主它就指向敌城甚至变 null。

**修法**：两次兜底 —— 目标城不属于本势力 → `GetNearnestForceCity()`；
目标为 null 且 `CityCount > 0` → `GetNearnestForceCity()`。

**教训**：派生字段在跨对象状态变更后可能变脏，使用前必须重新校验它指向的对象是否仍满足语义。

出处：`City.cs:2355-2367`，对齐 `s11_sys_scen_person.cpp:909`。

## 6. 死配置：最后一城抓捕率

**现象**：`captureChangceWhenLastCityFall` 改了没反应。

**根因**：唯一使用点在 `escapeCity != null` 分支内，而"最后一城"时 `escapeCity == null` —— 永远读不到。
原版最后一城本来就是"全员必俘、不掷骰"（`s11_sys_event_capture.cpp:452-456`），不需要概率。

**修法**：删除该配置，只保留 `captureChangceWhenCityFall` 一档。

**教训**：加配置前先确认使用点的可达条件。写在不可达分支里的配置是负资产。

出处：`City.cs:2390-2399`。

---

## 7. 掠夺把农业商业也清了

**现象**：城破后城市开发度大幅下降，与原版手感不符。

**根因**：把"掠夺金粮兵"和"摧毁内政设施"混为一谈，顺手按随机权重缩放了 `agriculture` / `commerce`。

**修法**：只结算金 / 粮 / 兵力 / 兵装四项。开发度不动 —— 原版城陷只毁设施（`:280-341`），
城市本身的开发值保留。

**教训**：原版没有"城破掉开发度"这条；不要把多个副作用合并成一个函数。

出处：`City.cs:2661-2680`。

## 8. 异族打下白城

**现象**：异族部队攻破无主据点后，白城被异族"占领"，而其势力不该拥有据点。

**根因**：白城分支没有区分攻方是否 normal。

**修法**：`banditFall` 时直接 `return`，不占领。
对齐 `bandit_ignores_empty_kyoten`（`s11_sys_unit_action.cpp:222-230`）。

**教训**：原版里 `is_normal()` 是一等公民 —— 掠夺、设施保留率、改旗、入城、白城判定全都要分叉。
在任何城陷相关分支里，先问一句"异族/贼走这里吗"。

出处：`City.cs:2312-2335`。

---

## 9. 势力灭亡后残留冻结部队

**现象**：亡国后地图上还有该势力的部队，永远不动、永远不接任务。

**根因**：`troop.BelongForce` 由主将实时推导（`Leader?.BelongForce`）。
主将已脱离部队（被俘流转 / 阵亡 / 旧档中间态）时 `BelongForce` 为 null，
`troop.BelongForce == 本势力` 判定全部漏掉。

**修法**：增加兜底口径 —— 主将为 null 时按副将归属判定（此刻武将尚未全量脱籍）。

**教训**：以"派生字段"为判据的清理循环，必须考虑派生链断裂（主将为 null）的情形。

出处：`City.cs:2410-2436`。

---

## 10. 事件派发早于数据落定

**现象**：`OnCityFall` 订阅方拿到的 `city.BelongForce` 还是旧势力。

**根因**：`GameEvent.OnCityFall` 被放在改旗之前派发。

**修法**：派发点固定在 `OnFall` 末尾（改旗 → 入城 → 港关同步之后）。

**教训**：事件的语义是"状态已落定，通知外部刷新"。放在状态变更中间等于制造不一致窗口。

出处：`City.cs:2781-2783`。
