    使用说明 / 已知坑位
    
        
    
            
    基本流程
    
            
      
                
    1. 顶部选择挂载位置（特技 / 技法 / 建筑），根容器对应 actionEntities 或 effects。
      2. 
                
    2. 从左侧节点库把节点拖到画布（顶部标签页可切换 效果 / 触发器 / 条件）；容器节点（触发器 + 效果）内部还有「触发时机」「执行效果」两个放置区。
      3. 
                
    3. 选中节点，在右侧填写参数；带 * 的为必填。
      4. 
                
    4. 底部实时预览 JSON，点「复制」粘回对应配置文件。
      5. 
                
    5. 窄屏（手机 / 平板竖屏）下三栏会合并为单栏，用顶部 节点库 / 编辑区 / 属性 切换；触屏不支持拖拽，请点节点右侧的 ＋ 直接添加节点。
      6. 
            
    
            
    注意事项（源码层面）
    
            
      
                
    • 注册名即类名：绝大多数 class 名与类名一致，但 PersonAttributeCompare 对应的类名是 PersonAttributeCheck，导入时会自动识别。
      • 
                
    • 必填数组：andList / orList.list、SkillIdInList.ids、TroopAddBuff.values / weight 在 C# 中没有判空，缺失会空引用，编辑器会强制输出并校验。
      • 
                
    • and / or 是二元结构（固定 L / R 两个字段），andList / orList 是数组（list 字段），两者不可混用。
      • 
                
    • 同类字段语义不同：tartgetType（建筑系，阵营）与 targetType（部队系，行动方/目标方）拼写与含义都不同；isDefender 在部分类中是 int，在 TroopChangeMorale 中是 bool。
      • 
                
    • 单位：标注「万分比」的字段 10000 = 100%；标注「百分比」的字段 100 = 不变。概率类（ProbabilityCheck / TroopAddBuff.probability）为万分比，chance 为百分比（0~100）。
      • 
                
    • 不可用类：TroopAttributeCheck、TerrainHeightCheck、SkillIsSuccess、ResourceCheck、TimeCheck、TriggerList 等未注册或已注释，导入时会提示，不会出现在节点库。
      • 
                
    • FactionCheck 仅 ally / enemy 有效，其余值恒为 false。
      • 
                
    • 本工具只生成 JSON 字符串，不直接修改任何配置文件；粘贴前建议用 Git 确认差异。
