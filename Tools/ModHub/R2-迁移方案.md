# 把模组文件与封面迁到 Cloudflare R2 —— 落地方案

> 目标：让 zip 与封面这类大流量资源不再经过轻量服务器出口，服务器只负责几 KB 的 API 与 JSON。
> 前提：代码里已内置存储抽象层（`server/src/service/storage.ts`），本次是**配置 + 数据迁移**，不是改造。

---

## 0. 三句话结论

1. **R2 是这个场景的最优解**：S3 协议完全兼容（现有适配器直接用），且**出站流量免费**——模组站最大的成本项直接归零，只按存储量付费。
2. **客户端与网页零改动**：`/mods/{id}@{version}.zip` 与 `/posters/{hash}.ext` 仍走原地址，只是响应从"服务器吐文件"变成 **302 跳到 R2**；Unity 的 `UnityWebRequest` 默认跟随 302（`redirectLimit=32`），已实测。
3. **可秒级回滚**：迁移是"复制到 R2"而不是"搬到 R2"，本地文件全部保留；把 `.env` 改回 `local` 重启即回到现状。

---

## 1. 为什么是 R2（而不是继续用轻量服务器 / 换 COS）

| 方案 | 存储 | 出站流量 | 说明 |
|---|---|---|---|
| 轻量服务器直出 | 已付 | 打满就拖垮 API 与网页 | 出口仅 3–8Mbps，一个 111MB 头像包要 4.6 分钟，5 人同下就满 |
| 腾讯云 COS + CDN | ~0.1 元/GB/月 | ~0.15–0.25 元/GB | 需自己配 CDN 与防盗链 |
| **Cloudflare R2** | $0.015/GB/月 | **$0（免费）** | 域名已接入 Cloudflare 时最省心；缓存由 CF 边缘自动完成 |

模组站的流量特征决定了 R2 的优势：**下载多、上传少、内容不变**（`{id}@{version}.zip` 是天然不可变路径）。50GB 存储的月成本约 **$0.6**（R2 免费额度含 10GB 存储 / 100 万 Class A / 1000 万 Class B）。

## 3. 需要做的改动（共 3 处）

### 3.1 装依赖

```bash
cd /opt/sango-modhub/server
npm i @aws-sdk/client-s3
```

### 3.2 代码：补两行 R2 兼容配置

`server/src/service/storage.ts` 的 `ensureClient()` 里，`new mod.S3Client({...})` 增加 checksum 策略：

```ts
this.client = new mod.S3Client({
  region: s3.region || 'auto',
  endpoint: s3.endpoint || undefined,
  forcePathStyle: s3.forcePathStyle,
  credentials: { accessKeyId: s3.accessKeyId, secretAccessKey: s3.secretAccessKey },

  // AWS SDK v3.729+ 默认给 PutObject 附加 CRC32 校验头（x-amz-checksum-crc32）。
  // R2 对这种"灵活校验和"的支持随版本变化，遇到 501 / SignatureDoesNotMatch / checksum 报错时
  // 用下面两项退回"仅在上传方要求时才计算"，兼容性最好。
  requestChecksumCalculation: 'WHEN_REQUIRED',
  responseChecksumValidation: 'WHEN_REQUIRED',
});
```

> 若确认当前 R2 已正常接受校验头，这两项也可以不加；建议先按上面配置跑通，避免排错时绕远路。

`config.ts` 中 `s3.forcePathStyle` 默认是 `false`。R2 的 S3 端点（`<account>.r2.cloudflarestorage.com/<bucket>/<key>`）以 path-style 形式使用最稳、官方示例也是如此，因此靠环境变量显式开启（见 3.3），不必改代码。

### 3.3 环境变量（`.env`）

```ini
# 分发形态：对象存储 + CDN
STORAGE_DRIVER=s3
CDN_BASE_URL=https://cdn.yourdomain.com        # R2 绑定的自定义域（见 §4）

# R2（S3 兼容）：<ACCOUNT_ID> 在 Cloudflare 控制台右上角
S3_ENDPOINT=https://<ACCOUNT_ID>.r2.cloudflarestorage.com
S3_REGION=auto
S3_BUCKET=sango-modhub
S3_ACCESS_KEY_ID=<R2 令牌的 Access Key ID>
S3_SECRET_ACCESS_KEY=<R2 令牌的 Secret Access Key>
S3_FORCE_PATH_STYLE=true                        # 建议开启（R2 官方示例为 path-style）
```

⚠️ **`STORAGE_DRIVER=s3` 与 `CDN_BASE_URL` 必须同时配置**。只切 driver 不配 CDN 时，`publicUrl()` 会退回拼接 S3 API 端点（`https://xxx.r2.cloudflarestorage.com/bucket/key`），那是需要签名的私有端点，客户端会拿到 403。

## 4. Cloudflare 侧配置

1. **建桶**：R2 → Create bucket，名字与 `S3_BUCKET` 一致（桶名全小写）。
2. **建 API 令牌**（R2 → Manage API Tokens → Create）：
   - 权限选 **Object Read & Write**，**只授权这一个桶**（不要用 Account 级全局令牌）。
   - 记下 Access Key ID / Secret Access Key / Account ID。
3. **绑自定义域**（R2 bucket → Settings → Public Access → Custom Domains）：
   - 用 `cdn.yourdomain.com` 这类子域。**域名必须托管在 Cloudflare**（NS 指过来），否则无法绑定。
   - 绑好后不要用 `pub-xxxx.r2.dev` 那个开发域：它有速率限制且官方标注仅供测试。
4. **加一条 Cache Rule**（Rules → Cache Rules）：
   - 匹配 `cdn.yourdomain.com/*`
   - `Cache Eligibility: Eligible for cache`
   - `Edge TTL: Respect origin`（对象自带 `immutable, max-age=31536000`，命中后一年不回源）
   - 我们的路径本身就是不可变定址（`{id}@{version}.zip`、封面按 sha256 命名），所以永久缓存是安全的。
5. **防滥用**（R2 出站免费，但仍可能被人当图床）：
   - WAF 自定义规则：仅允许 `GET` / `HEAD`，其余方法 Block；
   - 可选：对 `cdn` 子域加 Rate Limiting（免费版可用一条）；
   - 由于 zip 与封面都是公开内容，**不用签名 URL**（客户端拼的是明文地址，上签名必须改客户端）。

> ⚠️ 唯一必须自查的点：R2 绑自定义域后，缓存是否真的生效。验证方式见 §7 第 3 条。

## 5. 存量数据迁移脚本

原则：**复制而非移动**（本地保留即可秒级回滚）；幂等（已存在可覆盖）；先干跑再真传。

建议落成 `server/scripts/migrate-to-r2.mjs`：

```js
/**
 * 把本地 data/files 下的对象复制到 R2（不删除本地文件，保证可回滚）
 * 用法：
 *   node scripts/migrate-to-r2.mjs --dry-run     # 只列出将要上传的对象
 *   node scripts/migrate-to-r2.mjs               # 真正上传
 */
import fs from 'node:fs';
import path from 'node:path';
import { PrismaClient } from '@prisma/client';
import { S3Client, PutObjectCommand, HeadObjectCommand } from '@aws-sdk/client-s3';
import dotenv from 'dotenv';

dotenv.config();

const DRY = process.argv.includes('--dry-run');
const LOCAL_ROOT = process.env.MIGRATE_LOCAL_ROOT ?? path.resolve(process.cwd(), '../data/files');
const IMMUTABLE = 'public, max-age=31536000, immutable';

const prisma = new PrismaClient();
const s3 = new S3Client({
  region: process.env.S3_REGION || 'auto',
  endpoint: process.env.S3_ENDPOINT,
  forcePathStyle: true,
  credentials: {
    accessKeyId: process.env.S3_ACCESS_KEY_ID,
    secretAccessKey: process.env.S3_SECRET_ACCESS_KEY,
  },
  requestChecksumCalculation: 'WHEN_REQUIRED',
  responseChecksumValidation: 'WHEN_REQUIRED',
});
const Bucket = process.env.S3_BUCKET;

const MIME = {
  '.zip': 'application/zip',
  '.png': 'image/png',
  '.jpg': 'image/jpeg',
  '.jpeg': 'image/jpeg',
  '.webp': 'image/webp',
};

/** 对象清单完全以数据库为准，避免磁盘上残留的孤儿文件被一起搬走 */
async function collectObjects() {
  const versions = await prisma.modVersion.findMany({ select: { fileKey: true } });
  const mods = await prisma.mod.findMany({ select: { posterUrl: true } });

  const keys = new Set();
  for (const v of versions) if (v.fileKey) keys.add(v.fileKey);
  for (const m of mods) {
    // posterUrl 形如 /posters/<sha256>.webp → 去掉前导斜杠就是对象 key
    if (m.posterUrl) keys.add(m.posterUrl.replace(/^\/+/, ''));
  }
  return [...keys];
}

async function exists(key) {
  try {
    await s3.send(new HeadObjectCommand({ Bucket, Key: key }));
    return true;
  } catch {
    return false;
  }
}

async function upload(key) {
  const local = path.join(LOCAL_ROOT, key);
  if (!fs.existsSync(local)) return { key, skipped: '本地缺失' };

  const size = fs.statSync(local).size;
  if (DRY) return { key, size, action: '将上传' };

  await s3.send(
    new PutObjectCommand({
      Bucket,
      Key: key,
      Body: fs.createReadStream(local),
      ContentType: MIME[path.extname(key).toLowerCase()] ?? 'application/octet-stream',
      CacheControl: IMMUTABLE,
    }),
  );
  return { key, size, action: '已上传' };
}

async function main() {
  if (!Bucket || !process.env.S3_ENDPOINT) {
    console.error('缺少 S3_BUCKET / S3_ENDPOINT，请先按 .env.example 配置');
    process.exit(1);
  }

  const keys = await collectObjects();
  console.log(`待处理对象 ${keys.length} 个${DRY ? '（dry-run）' : ''}\n`);

  let ok = 0;
  let bytes = 0;
  for (const key of keys) {
    try {
      if (!DRY && (await exists(key))) {
        // 已存在则跳过：不动线上对象，重复执行安全
        console.log(`  跳过（R2 已有）  ${key}`);
        continue;
      }
      const r = await upload(key);
      if (r.size) bytes += r.size;
      if (r.action) ok += 1;
      console.log(`  ${r.action ?? r.skipped}  ${key}${r.size ? `  ${(r.size / 1024 / 1024).toFixed(2)} MB` : ''}`);
    } catch (e) {
      console.error(`  失败  ${key} —— ${e.message}`);
    }
  }

  console.log(`\n完成：成功 ${ok} 个，合计 ${(bytes / 1024 / 1024).toFixed(1)} MB`);
  await prisma.$disconnect();
}

main().catch(async (e) => {
  console.error('迁移失败：', e);
  await prisma.$disconnect();
  process.exit(1);
});
```

要点：

- **对象清单以数据库为准**（`modVersion.fileKey` + `mod.posterUrl`），而不是扫磁盘目录——磁盘上可能有已下架模组残留的孤儿文件，没必要搬。
- `--dry-run` 先看清单与总体积，确认没漏再真传。
- 上传后对象自带 `immutable` 缓存头，Cloudflare 边缘一次回源后长期命中。
- 大包建议单线程顺序传（脚本默认如此），避免把服务器出口带宽全部占满影响线上 API。

## 6. 切换与回滚步骤

```
阶段 A（不影响线上）
  1. 建桶、建令牌、绑自定义域、配 Cache Rule        §4
  2. npm i @aws-sdk/client-s3                        §3.1
  3. 改 storage.ts 的 S3Client 选项（checksum 策略）  §3.2
  4. 干跑迁移脚本，核对清单与体积                     §5
  5. 真实执行迁移（此时线上仍是 local 直出，无感）

阶段 B（一次切换，分钟级）
  6. 改 .env：STORAGE_DRIVER=s3 + CDN_BASE_URL + R2 三项 + S3_FORCE_PATH_STYLE=true
  7. pm2 restart sango-modhub
  8. 按 §7 验证

阶段 C（观察后收尾）
  9. 观察 1–2 周（下载、封面、发布、删除模组各走一遍）
 10. 确认无误后，再考虑清理 /opt/sango-modhub/data/files（建议先打包留份备份）
```

**回滚**：把 `.env` 改回 `STORAGE_DRIVER=local` 且清空 `CDN_BASE_URL`，`pm2 restart`。因为本地文件一个都没删，回滚是秒级的。

## 7. 验证清单

```bash
# 1) 形态确认：storage=s3、cdn 是你的自定义域
curl -s http://127.0.0.1:8081/health

# 2) 下载端点应返回 302，Location 指向 cdn 域
curl -s -o /dev/null -D - "http://127.0.0.1:8081/mods/<某模组id>@<版本>.zip" | head -6

# 3) 封面同样应 302
curl -s -o /dev/null -D - "http://127.0.0.1:8081/posters/<某封面hash>.png" | head -6

# 4) 缓存是否生效：第二次请求看 cf-cache-status（应为 HIT），且 age 在增长
curl -s -o /dev/null -D - "https://cdn.yourdomain.com/posters/<hash>.png" | grep -i -E 'cf-cache-status|age|cache-control'

# 5) 客户端协议仍然正确（url 字段 + auther 拼写 + size 为数字）
curl -s "https://modhub.yourdomain.com/market/mod_list.txt"

# 6) 端到端：网页发一个新模组 → 其 zip 应直接落到 R2（R2 控制台能看到 mods/<id>/<version>.zip）
```

另外确认一件事：**服务器出口带宽占用应显著下降**（大文件不再经过它）。

## 8. 成本估算（以官网实时报价为准）

| 项 | 单价 | 50GB 存储 + 1TB 下载的场景 |
|---|---|---|
| 存储 | $0.015/GB-月 | ~$0.6/月（前 10GB 免费） |
| Class A（写入） | $4.5/百万 | 发布次数极少，忽略 |
| Class B（读取） | $0.36/百万 | **缓存命中不回源**，实际接近 0 |
| 出站流量 | **$0** | $0 |
| Cloudflare CDN | 免费版即可 | $0 |

对比现状（轻量服务器带宽打满导致 API 连带变慢）——这是**用钱换不来**的稳定性改善。

## 9. 风险与注意

| 风险 | 说明 | 对策 |
|---|---|---|
| 只切 driver 没配 CDN | 客户端拿到需要签名的私有端点 → 403 | 两者必须同时配（§3.3 已强调） |
| checksum 不兼容 | 部分 SDK / R2 组合会报校验错误 | `requestChecksumCalculation: 'WHEN_REQUIRED'` |
| 缓存不生效 | 自定义域没配 Cache Rule，每次都回源 R2 | §7 第 4 条用 `cf-cache-status: HIT` 验证 |
| 域名未接入 Cloudflare | R2 自定义域无法绑定 | 必须把域名 NS 托管到 Cloudflare，或用 r2.dev（仅测试） |
| 被当免费图床 | 出站免费不等于无限滥用 | WAF 只放行 GET/HEAD + 可选限速 |
| 服务器上传占用出口 | 发布 200MB 包时占用轻量机上行 | 一次性行为、顺序上传，可接受 |
| 迁移期间新发布的模组 | 阶段 A 期间新发布的对象会落在**本地** | 阶段 A 之后、切换前补跑一次迁移脚本即可（脚本幂等） |

## 10. 后续可选优化（本次不做）

1. **客户端直传 R2**（presigned URL）：网页/游戏内上传时先向服务端要签名，再由浏览器直接 PUT 到 R2，服务器完全不中转。收益是上传不再占服务器带宽，代价是要改客户端（游戏内发布走 `WWWForm` 到我们 API，改造成本高），且需要在 R2 配 CORS。
2. **多档封面**（160/320/640 webp）：在 R2 上用 Cloudflare Image Resizing 或上传时生成，列表页不再拉大图。
3. **历史版本 GC**：保留最近 N 个版本的 zip，老版本转 R2 Infrequent Access 类别（存储更便宜，取回有费用），或直接清理。
4. **下载统计去 CDN 化**：CDN 命中时服务器收不到请求，`DownloadLog` 会少记；如需精确统计，可让 CDN 打日志后离线聚合，或接受"只统计回源次数"。
