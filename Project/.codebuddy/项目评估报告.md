# Sango Infinity 项目评估报告

> 生成日期：2026-09-24
> 说明：本文档由代码盘点 + 关键结论源码复核 + 内容量统计生成，供项目负责人评估与批注。
> 数据侧（`Build/Content/Data`、`Data/scenario/*`）不在仓库内，"内容量"为按 JSON 条目数的近似统计；三国志11 对比部分基于对 311 机制的认知，具体细节请以实际为准。

---

## 一、结论先行（Top 10）

1. **内容量不是短板**：特技 ~100、建筑类型 ~65、官职 ~81、技能/战法 ~30、科技 ~36、宝物 ~67、兵种 ~26、武将库 ~832、AI 权重表 ~212 项，量级与三国志11 相当。
2. **真正的差距在"接线"而非"内容"**：外交动作 11 种只接通 4 种（`Game/System/Diplomacy/DiplomacyManager.cs:156-172`）；外交事件系统 `Init()` 整体注释（`DiplomacyEventManager.cs:33-42`）；AI 外交被显式屏蔽（`Game/Object/Force/Force.cs:699-700`）；剧本事件引擎是空壳（`Game/Scenario/ScenarioEvent.cs:293-301`）。
3. **最大工程风险是"主循环会被表现层卡死"**：`Scenario.Run` 首行 `RenderEvent.Update` 返回 false 就整帧 `return`（`Game/Scenario/Scenario.cs:1431`、`Game/Render/RenderEvent/RenderEvent.cs:83-84`），且事件池复用被注释、队列用 `RemoveAt(0)`（`RenderEvent.cs:87-89`）。
4. **存档没有版本号与迁移机制**：`ScenarioInfo` 无 version 字段，仅 `ShortScenario.cs:156` 有 `versionCode<6` 分支；`GainValueConfig.cs:17` 自述靠"字段只能追加"的口头约定。
5. **读档复位不彻底**：`Window`/`GameDialog`/`GameLanguage`/`ModManager`/`ScenerioEventManager` 等单例与 `GameEvent` 静态委托不随 `OnGameShutdown` 清理，二次开局会叠加监听。
6. **存在一个"打开了就灾难"的开关**：`Scenario.useThreadRun`（默认 false、全项目无人置 true）一旦启用即用 `Task.Run` 跑主循环，跨线程读写游戏对象（`Scenario.cs:1199-1217`）。
7. **结构性缺失集中在"战场形态"**：阵型（0 实现）、天候联动（未接线）、落石/水攻/陷阱（地图字段在、代码全注释）、战法暴击（TODO 直接 `return false`，`Game/Object/Troop/Troop.cs:1396-1409`）。
8. **强项被低估**：单挑（`Game/Duel`）与舌战（`Game/Debate`，能**改判外交与登用结果**，`DebateConsequence.cs:52-54/91`）实现度很高；编辑器与 Mod 管线成熟。
9. **工程卫生是长期成本项**：4 个 God 类（City 158.9KB / CityAI 105KB / Person 97.5KB / ForceAI 96KB）、27 个同构 `*SelectSystem`、无测试无 CI、53 处 `Debug.Log` 绕开日志系统、45 处 TODO/待实现。
10. **有一批"死代码/半成品"在干扰判断**：`Military` 类零引用、`GameBattle` 空壳、`Title`（爵位）只有数据无效果、`popularSupport`（民心）参与计算但无任何改变来源、灾害枚举存在但零实现。

## 七、与三国志11 的功能差距

### A. 结构性缺失

| 311 机制 | 本作 | 影响的体验 |
|---|---|---|
| 阵型系统 | 0 实现 | 排兵布阵的策略感 |
| 天候系统 | 字段在、无驱动 | 战法/计略的随机博弈 |
| 地形陷阱联动（落石/水攻/堤防/陷阱） | 地图字段存在、分支全注释 | 以少胜多的地形战术 |
| 统一/结局演出与评分 | 只有一行日志 | 通关正反馈与重玩动力 |
| 历史/随机事件引擎 | 空壳 | 311 的灵魂：剧本演剧性 |
| 势力独有科技/特色 | `Technique.kind` 仅分类 | 势力差异化 |

### B. 有骨架未接通（改造成本低、收益明显）

- 外交 11 种动作 → 只 4 种可用（`DiplomacyManager.cs:156-172`）
- 外交事件管理器 `Init()` 被注释、事件硬编码（`DiplomacyEventManager.cs:33-42`）
- AI 外交被显式屏蔽（`Force.cs:699-700`）
- 战法暴击 `return false`（`Troop.cs:1396-1409`）
- 赎回/换俘未实装（`CityDiplomacyRansom.cs:6/82`）
- 爵位 `Title` 有数据无效果
- 民心 `popularSupport` 无改变来源

### C. 有实现但特征偏弱

| 项 | 现状 | 建议对标 |
|---|---|---|
| AI 难度 | 只做"送资源 + 玩家伤害系数 + 单挑倾向" | 311 的侵略性/结盟倾向/发育节奏 |
| 经济 | 无物价波动、无市场博弈 | 311 的商人/物价/粮价差 |
| 外交关系 | `RelationMap` ±5000 与设计文档 ±2000 不一致 | 统一并让 UI 语义可读 |
| 特技 | 框架 + 100 条数据 | 校验覆盖率与战斗类装配 |

### D. 已达标甚至超出 311

- **单挑**：触发（指令/事件/战法命中）、叫阵流程、拒绝代价、AI 抉择、受伤/死亡/捕获、表现层
- **舌战**：能改判外交与登用结果（`DebateConsequence.cs:52-54/91`）
- **编辑器 + Mod 管线 + Excel 数据管线**
- **内容量**：特技/建筑/官职/宝物/兵种/武将数量都在 311 量级

**一句话判断**：现状像"311 的系统骨架 + 更细的单挑舌战 + 更强的编辑器"，但缺了让玩家记住 311 的三件事：**阵型/天候/地形博弈、历史事件的演剧性、统一的通关叙事**。

## 十、建议路线图
